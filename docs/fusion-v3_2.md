## 为什么这次需要程序入口

此前 paired_only 路线跳过固定降彩度和高光压缩，以免把已适配环境的候选重复压灰。这一默认策略继续保留。用户现在明确指出颜色过鲜艳、物体细节过于清晰，为定向局部校正提供了具体反馈；因此增加独立开关，不重新启用旧固定表面分区调色。

旧提示词把气瓶29°、阀门12°等初始提案写成硬目标。新的 support_first 预览提示词将这些数字标为名义参考，并限定原区域内的微调；承托优先，不能为了角度制造空气缝、移动钢件或新增支撑。

## 局部外观算法

实现：`src/fusion_engine/controlled/camera_feedback.py`，接入 `prepare_foreground`。

1. 读取显式 `feedback_correction`。开关缺省/关闭时返回原候选，不改变旧路径。
2. 没有当前候选可见轮廓时跳过，不拿计划Mask当成实际实体。
3. 每件物体的目标是：当前可见轮廓 ∩ 当前外观目标 ∩ 编辑授权 − 保护区 − 原前景。
4. 浮点CIELAB中保持L通道，将a/b乘以显式系数，减少彩度并尽量保持色相。RGB量化/色域裁切仍可能带来微小偏差；这不是物理反射率求解。
5. 对实体内部做归一化加权高斯软化：`G(I*M) / max(G(M), eps)`。只把结果写回实体像素，孔洞与背景不参与混色。
6. 不改变Alpha、Mask、孔洞、几何、接触或画布，不添加随机噪声；不声称估计了监控相机的真实MTF。
7. 保存实际作用像素、参数与处理前后彩度分位数。统计量不能独立证明自然度。

当前预设：S01彩度系数0.78，S20系数0.74；细节软化sigma均为原画布1.2像素。允许配置范围分别为0.65–1与0–1.5像素。这些是保守的工程提案，没有声称自动寻得最优值。

归一化软化主要处理实体内部的过密微纹理。它不能修正生成时的错误轮廓、姿态、物体几何，也不能完整重建监控镜头的成像过程。薄轮辐仍保持实体，不通过模糊删除结构。

```json
{
  "harmonization": {
    "feedback_correction": {
      "enabled": true,
      "reason": "用户明确指出物体颜色鲜艳、有效清晰度高于环境",
      "object_ids": ["S01"],
      "chroma_scale": 0.78,
      "detail_sigma_px": 1.2
    },
    "blur_sigma_px": 0
  }
}
```

这是局部字段示例；可运行任务使用 `config/controlled/v3_2/S01.json` 或 `S20.json`。

禁止与旧 `blur_sigma_px` 重复软化；存在旧表面控制时，要求 `surface_policy=paired_only`，防止两套降彩度叠加。物体ID必须有效且唯一。

## 承托优先的边界

`placement.priority=support_first` 只允许A模式预览，要求承托检查、独立编辑包络和明确微调范围。当前中心最大归一化移动距离0.03、尺寸比例0.85–1.15、投影角度变化±25°。

这是生成提示词的摆放请求，尚不是自动三维落位算法或已核验的新姿态。现有几何/接触/保护门禁没有放宽，原Mask和接触授权不会自动随物体移动。实际改变较大的姿态仍需重新规划并审核接触和Mask；不能把新姿态通过本预设自动升级为合格结果。超出原授权时仍拒收，证据不足仍UNKNOWN。

## 画幅与像素的区别

程序母版继续是3840×2160，不裁切。用户所说“像素偏高”按物体相对背景过锐、纹理过细处理，不缩小最终画布。

本轮GPT原始返回均为1672×941。确认全视野且比例误差约0.053%后，对整幅图显式重采样到3840×2160；没有裁切，也没有把它称为原生4K。原始文件单独保留。
