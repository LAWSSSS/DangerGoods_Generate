# 结构保留与按阶段纠正：0.8.0 / 可选 V3.1 路线

日期：2026-10-18。任务 Schema 仍为 2.0，基础分层合成 Pipeline 仍为 3.0。
本文件描述本次实际代码，不把设计建议写成已执行的模型内部操作。

## 1. 为什么改这一层

历史阀门原始候选中已有手轮轮缘、轮辐和阀杆，后处理却将部分连接恢复成背景。
原因包括：VLM 粗孔洞被写成确定背景，部件细化继续冻结这些负空间，以及迭代只看
`APPLIED` 就继承处理母版。增加生图要求无法修复这种确定性的后处理删除。

另一个问题是统一压低彩度和高光会削弱已经适配现场的残漆和锈层，但不能求解真实重照明。
本次先做 GPT 参考，再针对这些可确认的缺陷修复程序。

## 2. GPT 参考的实际操作

- S01、S20 各调用内置图像工具 3 次，共 6 次；未调用 OpenAI API，也未替换私有 YAML 的模型。
- 首轮输入完整背景与生锈六视图，直接生成融合图，未使用本程序的分割和调色。
- 之后每轮重新提供原背景、原六视图、选定候选；完整 Prompt 逐字保留并追加一个主要修正目标。
- 调用前写入 Prompt、输入哈希、图像职责、时间和目标；返回后保存工具原图、响应中实际可得的字段和人工可读检查。
- 两件均选第 2 轮作视觉参考，第 3 轮没有证明整体更好。不是自动选择最新图。
- 返回原图均为 1672×941。确认视野和近似长宽比后整幅归一化到 3840×2160，没有裁切；不称为原生 4K。
- GPT 阀门保留了可见闭合轮缘与连接，气瓶保留了暗红漆和锈层体积；位置、气瓶厚度/文字及局部背景重绘仍有问题。
- 工具没有提供底层型号、种子、改写 Prompt、去噪过程或内部思维链。这些字段明确记录为未提供。

这是一组视觉对照，不是严格像素锁定结果，也不是真实三维标定、手工蒙版或训练真值。
完整实时记录位于本次 `output/gpt-reference-repair-*`，其中 `GPT可观察方法与边界.md` 说明实际方法。

## 4. 孔洞证据与细结构

### 4.1 统一候选证据

`shape_evidence.candidate_evidence` 在原图坐标上构建按部件的可见结构见证像素：

1. VLM 外轮廓与部件范围只提供搜索区，孔洞先作为建议。
2. 候选与配准背景在外轮廓周围估计局部 RGB 中位偏移；不足 32 个样本时不估偏移。
3. 使用浮点 LAB；显式前景点周围半径 1 的真实候选像素，须与配对背景距离大于 8 才用于部件颜色学习。
4. 每部件最多 3 个颜色中心，固定随机种子；搜索区仅扩展局部采样范围，不膨胀最终形状。
5. 颜色见证须满足部件距离小于 12、背景距离大于 8、部件距离加 6 小于背景距离，且有色度变化或亮度升高的证据；显式有效前景种子优先。
6. 孔洞像素只有背景距离不大于 6、与已学前景距离至少 12 且有有限模型支持时，才成为确定背景。冲突处前景优先。

以上阈值当前属于估计器内部实现，不是普适物理常数。低对比度深锈、近似背景色、小尺度结构仍可能 UNKNOWN。

### 4.2 初始分割与细化共用规则

初始 GrabCut 和部件细化都复用相同证据：未经验证的孔洞仅为可修改的概率背景，不永久冻结。
部件外轮廓不会直接裁掉孔内轮辐；真实配对背景仍可保留为空洞。
没有整体填洞、最终 Mask 膨胀、手绘连接或把完整设计形状硬塞进候选的操作。

### 4.3 保存后结构保留

`structure_retention` 对原前景遮挡以外的部件见证，检查分割是否删去、合成是否精确恢复成原背景。
每部件至少 16 个见证像素；损失比例大于配置上限则 FAIL，证据不足 UNKNOWN。
非 PASS 不得作为结构验证通过的母版继承。

报告存为 `analysis/candidate-*.structure.json` 和 `postprocess_integrity`，见证另存 PNG。
PASS 只说明被采样的可见结构未被删除，不证明全部轮缘闭合、真实孔洞正确、身份完整或三维可承重。
合成真值测试检查真实孔洞和闭合轮缘；真实照片仍需视觉复核。

## 5. 接触、阴影和光色

- 实体、接触带、投影接收面、原前景与 protect 继续分别授权；最终重新解码检查实际变化区。
- 支撑整体为 UNKNOWN，但某个独立接触已经 PASS 时，可以只使用该接触；任何真实 FAIL 不因此放行。
- 未知接触不补黑影。投影估计证据不足继续 UNKNOWN，不降低既有可靠度门槛。
- `processing.interaction_effects` 报告接触、投影和前景的实际生效像素。零像素不代表相应交互不需要。
- `paired_only` 跳过固定的表面色度/高光压缩，仅允许现有可靠的同背景配对、有界校正。没有物理重照明求解。
- 原始候选的错误颜色、错误高光和悬浮若未被生成器修正，仍然是失败，不能由调色 PASS 掩盖。

## 6. 缺陷归因和父候选

`repair_diagnosis` 比较处理前的候选观察、分割/保存后结构，以及处理后意见：

| 证据 | 归因/处理 |
|---|---|
| 原候选身份、支撑、遮挡或颜色 FAIL | 生成问题，下一轮带原参考纠正 |
| 候选见证被 Mask 删除 | 分割问题，原母版不可继承 |
| 超出 Mask 删除量的精确背景恢复 | 合成问题 |
| 候选色彩 PASS、母版有光色缺陷意见 | 调色或模型意见分歧，需对照 |
| 越界/处理未完成/信息不足 | 保留诊断或 UNKNOWN，不制造修复成功 |

父候选选择规则：

1. 处理完成、结构 PASS、背景/画幅/实际层契约均 PASS，才考虑用母版；否则使用配准原候选。
2. 与已有父候选比较共享检查。至少一项改善到 PASS，且无新 FAIL、无原 PASS 退步，才能替换。
3. FAIL 变 UNKNOWN 不计作已经改善。无法证明改进时保留原父候选。
4. `selected_parent`、路径、哈希、输入阶段与原因逐轮记录；“用于修复参考”不等于“已验收”。
5. 若下一轮使用原候选，详细母版审阅仍留档，但不会把后处理误删直接写成原候选缺少该部件。

每次发送的 Prompt 仍以上次完整文本为精确前缀，追加块标明本次父候选。5000 字符上限在客户端预留三轮空间并拦截超长请求。
失败请求在网络调用前计入预算，无隐式重试。达到三轮或预算后停止并保留失败。

## 8. 交付边界

本次修复针对候选细结构误删、错误母版继承和重复固定调色。现有接口没有原生二值 inpaint、深度/法线控制或三维重照明。
背景像素锁定是本地分层恢复的结果；不能保证整个生成候选都保持背景，也不能保证恢复后仍有足够环境交互。
严格物理尺寸、真实三维承托、人工 Mask 与训练标注仍未获得独立证据。自动检查、模型意见和人工验收分别保留。
