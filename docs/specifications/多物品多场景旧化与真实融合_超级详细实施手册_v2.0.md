# 第一部分：真实案例与约束定义

## 1. 任务目标、原则与验收边界

### 1.1 合格的融合必须同时满足什么

对任意物品 $O$ 和场景 $S$，我们不是追求“看起来有物品”，而是追求以下性质同时成立：

1. **身份守恒**：物品的种类、主体轮廓和识别关键点仍然可辨；例如灭火器保留压力表、握把、软管的合理连接，罐体保留正确的人孔与接管位置。
2. **类别合理旧化**：金属可氧化、塑料可发黄划伤、木材可开裂受潮、玻璃可蒙尘污斑；不应把所有材质都处理成“红锈纹理”。
3. **尺寸可解释**：物品大小由真实尺寸信息、参照物、相机距离、投影姿态及任务目标共同决定，不以“模型生成得清楚”作为放大的理由。
4. **空间可解释**：能够指出物品被什么支撑、遮住谁、被谁遮住，有无压陷、接触缝隙和结构穿模。
5. **光照可解释**：新物体上的明暗、反射、投影方向与背景可见证据相符；未知光源时应承认不确定性。
6. **成像一致性**：景深、模糊、噪点、白平衡、曝光、压缩、锐化和镜头畸变不会把新物体“单独突出”。
7. **修改可追溯**：保存输入、提示词、配置、生成版本、人工修改、蒙版和验收结果；合成图应有标识，不能冒充未经修改的现场记录。

### 1.2 “无贴图感”不是“完全没有图层合成”

“贴图感”是最终视觉上的失败，不是技术工具本身的罪过。未经空间与光照处理的直接 Alpha 叠加通常失败；但**经过合理几何渲染、遮挡恢复、局部重绘、阴影与相机风格匹配的混合合成**同样可能产生非常自然的效果。反之，整图生成即使没有直接贴图，也可能出现尺度错误、部件幻觉和假接触。

### 1.3 定义三类目标，开始前必须选一种

| 模式 | 背景允许变化 | 物体结构要求 | 主要用途 | 默认优先技术 |
|---|---|---|---|---|
| A：视觉概念合成 | 允许局部甚至全图重绘 | 中高 | 方案展示/创意可视化 | 多图参考整图生成 |
| B：真实场景受控编辑 | 除物体及交互区域外保持不变 | 高 | 工业方案、样本扩充 | 背景锁定 + 遮挡建模 + Inpainting |
| C：严格标注合成 | 背景未编辑处逐像素不变 | 极高，需标签 | 检测/分割/学术数据集 | 明确的 2D/3D 几何、遮挡、Mask、差分验证 |

**操作**：新任务先在配置中写 `mode=A/B/C`。没有声明时，建议优先 B；如果用户要求“背景一丝不变”或自动生成训练集，则选 C。不要为了更自然而悄悄将 B/C 改为 A。

### 2.2【已执行】第一轮怎么生成

**输入**：六视图参考 + 废铁场景。**生成目标**：在背景废料堆中构造一台严重氧化、局部灰绿色金属底色的卧式压力罐，保留检修口、接口及支承结构，周围为杂乱废钢，并且采用与监控照片接近的粗糙、非商业摄影风格。

**操作过程**：

1. 以六视图说明“是什么物品”，明确卧式圆筒、曲面封头、检修人孔和多个法兰口是不可随意丢失的身份特征。
2. 以场景图说明“物品在哪里”，要求罐体被废钢环绕，不是独立摆拍，不需要完全露出底部支架。
3. 加入锈蚀、粉尘、划伤、污渍和残留金属光泽的视觉要求，不要求整件变成均匀亮橙色。
4. 要求周围废钢与罐体共同生成部分遮挡、压覆和接触暗部，不再用成品储罐裁切层平面覆盖背景。
5. 生成第一张 1672×941 的新图并进行目视检查。

**第一轮检查结论**：能够辨认罐体与锈蚀，但罐体在画面里太突出，部分纹理锐利、温暖色偏明显，视觉上与灰冷的监控环境不完全协调。生成标识（已有记录）：`277afc8a-73c2-4818-94e1-7fc9fe8e0550`。

### 2.3【已执行】第二轮如何修正

1. 保留“卧式罐体 + 圆形人孔 + 管口 + 支撑部位”的物体身份目标。
2. 加强混堆关系：罐体底部允许被条形金属和板片自然挡住，罐体背面仍要有可读的后景废料，不能完全浮在废钢之上。
3. 减弱商品摄影式过度干净的边缘，进一步强调陈旧、粉尘、斑驳锈蚀及监控画质。
4. 再发起一次生成式合成；这是**重新生成的第二张画面**，不是第一张图的固定蒙版局部修补。
5. 人眼检查结构、遮挡和尺度：第二轮主体略倾斜，可见若干接管、近端人孔和底部被覆盖的支撑；整帧仍偏暗、偏暖，所以进入颜色处理。

生成标识（已有记录）：`d31e3615-3712-46f7-989f-9e334dd74016`。本次两轮过程中没有可用的深度图、每步扩散噪声、3D 网格、条件权重或中间 Mask。不能据此虚构像素级的模型内部动作。

### 2.4【已执行】使用了哪些真实可复现的校色步骤

读入第二轮的 PNG → BGR 转 LAB → 按通道变换 → 转回 BGR → 高斯柔化 → JPEG 输出：

```python
im = cv2.imread(input_path)
lab = cv2.cvtColor(im, cv2.COLOR_BGR2LAB).astype(np.float32)
lab[:, :, 0] = np.clip(lab[:, :, 0] * 1.20 + 9, 0, 255)
lab[:, :, 1] = np.clip(128 + (lab[:, :, 1] - 128) * 0.92 - 2.5, 0, 255)
lab[:, :, 2] = np.clip(128 + (lab[:, :, 2] - 128) * 0.89 - 4.0, 0, 255)
bgr = cv2.cvtColor(lab.astype(np.uint8), cv2.COLOR_LAB2BGR)
bgr = cv2.GaussianBlur(bgr, (0, 0), 0.55)
cv2.imwrite(output_path, bgr, [cv2.IMWRITE_JPEG_QUALITY, 87])
```

这里是 OpenCV 8-bit LAB（L、a、b 各编码为 0–255，中性色度约 128），并不是用 CIE L* 的 0–100 量纲直接计算。全图 RGB 像素均值经复核如下：

| 图片 | 平均 R | 平均 G | 平均 B |
|---|---:|---:|---:|
| 原背景 | 122.30 | 121.14 | 118.05 |
| 第一轮 | 105.64 | 94.19 | 86.59 |
| 第二轮 | 100.54 | 88.28 | 79.76 |
| 校色版 | 118.68 | 116.76 | 114.15 |

**结果解释**：均值更接近说明“整体色调漂移有所减轻”，并不证明真实世界的光源、阴影或材质反射已经准确。滤波降低高频细节但可能损失物品检测相关特征；JPEG 编码能够模拟部分压缩观感，但不是对真实监控编码链路的完整复现。

### 2.5【已执行】对大小和贴图感到底做了什么

- **大小**：使用储罐自有结构比例 + 背景相对视觉关系做**定性**约束，生成后检查是否过大，再生成第二版。没有读到储罐毫米尺寸，也没有使用公式计算“应该占多少像素”或在接口提交了固定 OBB。
- **去贴图感**：通过“罐体与邻近废铁整图共同生成”的方式形成视觉遮挡与接触，而不是先扣成透明素材直接 Alpha 混合。最终的接触阴影是生成内容，**不等于执行了物理光线追踪**。
- **画风**：在生成要求中匹配场景物理质感，然后用真实运行的 LAB + 高斯模糊 + JPEG 质量参数使整帧偏色、过锐问题缓解。
- **代价**：周围原有废钢和监控叠字会部分被重绘；原图 2048×1152 与最终 1672×941 分辨率不同，因此谈不上逐像素保持原现场。

**由此获得的经验**：如用于工业数据集，更推荐后文的“显式几何约束 + 保留背景 + 明确遮挡 + 局部生成 + 指标闭环”，而不是把整图重绘默认为最优解。

## 3. 操作系统的输入、输出、证据与失败条件

### 3.1 单物体任务必须收集的信息

**最少输入**：物品参考图、背景图、目标旧化方式、是否保护背景。**强烈建议补充**：物品至少两个视角、已知尺寸或参照物、期望放置位置、照片是否存在需要锁定的文字/标志、是否做检测数据集。

每次输入建立：`object_id`（物体唯一 ID）、`source_views`（参考图清单）、`geometry`（尺寸与相对尺寸，含置信度）、`material_parts`（按部件的材质）、`scene_id`、`protected_regions`、`mode`、`output_size`。多物体时每个物体独立建立一个对象条目。

### 3.2 输出不能只有一张图片

建议每个样本输出 `final.png`、`object_mask.png`、`front_occluder_mask.png`、`contact_shadow_mask.png`、`edit_mask.png`、`placement.json`、`quality_report.json`、`provenance.json`、`prompts.txt`、`preview.jpg`。若生成模型或数据条件不支持真实 Mask，**必须在报告中标注缺失**，不能自动补一个猜测的轮廓伪装成真值。

### 3.3 项目不应隐瞒的失败状态

- `INSUFFICIENT_SCALE_EVIDENCE`：缺少尺寸/相机/参照物信息，仅能给宽范围视觉估计。
- `POSE_AMBIGUOUS`：视角不足，背面及接口的三维对应关系不清楚。
- `UNSUPPORTED_PLACEMENT`：放置位置不能承担重量，或接触关系矛盾。
- `OCCLUSION_CONFLICT`：同一位置相互遮挡次序自相矛盾。
- `IDENTITY_DRIFT`：关键部件错、数量错、左右镜像错。
- `BACKGROUND_CHANGED`：严格保护的区域产生像素变化。
- `PHOTOMETRIC_MISMATCH`：反光、阴影、锐度或颜色局部不相容。

出现失败状态时应退回对应步骤修复，而不是仅增加“更真实、超高清”等形容词。

## 4. 从开始到交付的总流程（推荐实施，非本次完整执行）

```text
S00 固化任务目标、证据等级与背景修改权限
  ↓

  ↓

  ↓
S03 解析场景：相机、深度线索、可放置区域、光照、参照物
  ↓
S04 选择对象-场景适配策略：支撑、重力、容纳空间
  ↓
S05 解算或限定目标尺度和投影包围框
  ↓
S06 确定姿态、几何投影与关键部件朝向
  ↓
S07 构建前后遮挡图、承重接触图和交互影响区
  ↓
S08 创建可编辑/受保护 Mask；为文字和证据区域加锁
  ↓
S09 按材质、环境、损伤历史构造非均匀旧化方案
  ↓
S10 匹配光照、投影、接触阴影、色彩与相机成像
  ↓
S11 选择生成路线：整图重绘 / 局部重绘 / 混合几何渲染
  ↓
S12 生成多个候选并自动/人工检查物体身份与物理逻辑
  ↓
S13 根据失败类型局部修复，而非无控制重复生成
  ↓
S14 统一成像与背景锁定恢复；尺寸、叠字复核
  ↓
S15 量化验收、边界案例人工复核、保存来源记录
  ↓
S16 交付图像 + Mask + JSON + 日志 + 验收报告
```

每个阶段建议约定四个接口：`输入`、`操作`、`输出`、`失败时退回点`。严格闭环的核心是**将生成模型提出的候选放到一组可验证条件中，而非让生成模型自己决定自己是否合格**。

# 第二部分：输入分析、尺度、透视与物理位置

## 5. S00–S01：任务建档、输入整理、可靠性检查

### 5.1 S00：用最少歧义固定需求（操作清单）

**步骤 1｜确认“物体身份必须保留到什么级别”**：检测数据集可能只要求类别真实；设备故障诊断可能要求接口数、握把方向、标签和损坏位置严格一致。由用户指定 `identity_level=category/component/instance`。实例级约束时，任何主要附件错位都应拒收。

**步骤 2｜确认背景能改多少**：对全图生成模式，不承诺像素保留；对局部编辑模式，明确允许改变的空间范围；对标注数据集，定义严格保护区域是否包括摄像头叠字和地面纹理。记录 `protected_regions` 而不是只写“不要改变背景”。

**步骤 3｜确认用途**：用于视觉展示可牺牲部分背景；用于目标检测训练需要导出真实的物体像素 Mask；用于结构审查需要保留部件数量；用于原始监控证据演示必须明确标注为“合成”，不可让观看者误认作未修改的现场记录。

**步骤 4｜确认物品材质和旧化目标**：同样是银色外表，可能是不锈钢、铝或镀锌钢；真实腐蚀形态不同。若材质不确定，将材质设为 `unknown_metal`，先获取用户说明或采用保守的积灰/刮擦方案，而不是默认满面红锈。

**步骤 5｜输出可审阅的任务说明**：一个 JSON 包含 `goal`、`mode`、`identity_level`、`object_count`、`preserve_overlays`、`allowed_damage`、`target_resolution`、`provenance_required`。所有后续生成提示都由该配置统一派生。

### 5.2 S01：检查图片并保留原文件

1. **只读备份**：将参考图和背景图复制到原始目录，计算 SHA-256；后续不得覆盖。将读入库版本、时间、尺寸写入元数据。
2. **尺寸/通道**：检查宽高、通道数、Alpha；尤其注意背景 JPG 是 RGB，六视图 PNG 可能是 RGBA，但不表示六个视角都具有有效透明分割。
3. **方向/EXIF**：读取 EXIF 方向，统一图像朝向；处理 EXIF 后保留变换矩阵，避免 Mask 与原图坐标错位。
4. **颜色空间**：转换前核实是否为 sRGB/ICC；OpenCV 默认 BGR 通道，不能把 BGR 当作 RGB 统计均值。
5. **压缩和模糊**：分区域测量锐度、噪点、块效应；JPEG 压缩边缘不等于真实物品的结构线。
6. **黑底/白底/六视图网格**：剔除多视图的文字标签、分隔线、展示底色对视觉分割的干扰。六视图用于几何理解，不要直接把一整张“六视图海报”当物品抠入背景。
7. **锁定不应改写的区域**：日期时间、编号、二维码、标识牌、用户指定区域单独定义保护 Mask。与物体重叠时先建立冲突处理规则，优先保护的文字不能被凭空“重新生成”。
8. **分辨率统一策略**：所有几何信息最终基于原始背景分辨率表示；若生成 API 只能输出较小尺寸，需保留 `source→generation→final` 的坐标变换。不能用较小生成图声称原背景全像素保真。

**输出**：`inputs_manifest.json`、原图哈希、颜色空间信息、原始及预览尺寸、重点区域清单。**失败处理**：参考图中关键件被裁切或角度不足，应补拍，不能靠生成器猜出准确部件。

## 6. S02：多视图物品解析与“身份守恒”约束

### 6.1 先分“整体主体—二级部件—细小特征”三层

对每个物品制作结构树，而不是只向模型写“一个生锈储罐”：

```text
Object: tank_001
 ├─ Primary geometry 主体
 │   ├─ cylinder：筒身
 │   ├─ left_cap：左封头
 │   └─ right_cap：右封头
 ├─ Distinctive components 身份关键部件
 │   ├─ manway：圆形人孔 / 紧固环
 │   ├─ nozzles[]：接口 / 法兰
 │   └─ saddles[2]：支架
 └─ Surface features 非刚体外观
     ├─ weld_seams：焊缝
     ├─ scratches：划伤
     └─ rust_dirt：污渍 / 氧化
```

**步骤 1**：对每个视图标注 `view_id`、观察方向、物体朝向、是否有透视畸变、是否完整可见。

**步骤 2**：跨视图匹配同一部件，例如前视角顶部三个小接口与俯视角同组三个接口的相对位置。记录 `keypoint_id` 与 `part_id`，不要把不同视图中的孔当成独立新孔。

**步骤 3**：为主体定义几何原语：长方体、圆柱、球、截锥、环、自由曲面等；复杂物体可以是多个原语组合。明确哪些形状**必须刚性保持**，哪些可以受旧化与物理变形影响。

**步骤 4**：定义允许改动清单：灰尘、局部腐蚀、表面划伤通常允许；法兰突然消失、灭火器握把翻转、钢瓶阀门位置改变通常不允许；严重废品若确实允许断裂，应明确 `structural_damage_allowed=true` 和断裂部位范围。

**步骤 5**：记录真实尺寸状态：`measured / catalog_verified / estimated / unknown`，真实尺寸必须带单位和来源。不要把六视图中的像素长度当作设备实际毫米数。

**步骤 6**：生成两套提示：`identity_positive` 列出必须保留部件，`identity_negative` 列出不可新增和不可删除部件。结构要求优先级应高于“锈得越重越好”。

### 6.2 多视图不是天然精确三维模型

六视图可能不是正交工程投影：它们可能来自不同拍摄距离、不同裁切或图像生成模型；无法保证真实长度比例。对于需要严格尺寸的场景，采用如下升级次序：

1. 有 CAD/产品图纸：直接导入已验证尺寸和三维装配关系。
2. 有可靠照片 + 标定相机：进行多视图几何估计，输出重建误差。
3. 只有多视图参考：使用几何原语拟合**大致结构**，把尺寸列为不确定。
4. 只有单视图：尽量选择与参考接近的目标观察角度；不可见面只适合低置信度生成。

### 6.3 不同几何类别要抓住哪些信息

| 类别 | 优先保留 | 难点 | 拒收症状 |
|---|---|---|---|
| 卧式罐/钢瓶 | 长径比、封头、法兰、支承和阀门 | 端面透视、遮挡支脚 | 接口漂移、椭圆端面不合理 |
| 灭火器 | 圆柱罐身、弯曲软管、阀头、提把、压力表 | 握把方向与软管连接 | 握把镜像、管线不连通 |
| 管道/弯头 | 管径、曲率、壁厚、端面法兰 | 近远端缩放、弯头自遮挡 | 管道断开、口径变化异常 |
| 框架/工具 | 杆件连接、齿口、孔位、轮廓 | 非凸几何、细杆穿模 | 重叠后结构断裂 |
| 箱体/电机 | 平面透视、棱边、轴/散热片 | 透视共点、多面材质 | 平行线与消失点矛盾 |
| 塑料桶/瓶 | 瓶口、把手、透明度、轮廓 | 透光、柔性凹陷 | 被错误赋予红锈 |
| 玻璃制品 | 厚度、折射轮廓、透射与背景畸变 | 透明物体与背景交互 | 玻璃不透明或影子过黑 |
| 织物/袋子 | 褶皱、缝线、材质厚度 | 重力垂挂、风向 | 悬空拉直、折痕不随接触改变 |

## 7. S03：把场景拆成“可放置空间 + 参照物 + 成像条件”

### 7.1 场景区域划分的具体步骤

**步骤 1：进行语义区域分析**。标识地面、墙、桌面、废料堆、货架、水面、天空、可移动物体、危险/禁止区域、叠字等。对废铁堆，不应假设可见下沿就是水平地面。

**步骤 2：提取候选支撑面**。例如地面、桌面、货架水平面、两根钢梁构成的支撑区域、斜坡、软沙面。需要记录支撑面的近似法向、倾斜度、材质、是否稳定、被遮挡程度。对杂乱堆积物，通常只有“局部支撑集合”，不能想象一整块平面。

**步骤 3：创建前景障碍图**。标识可能位于目标物体前面的钢条、绳索、网格、草叶、杆件、家具等。细长物体应该保留独立蒙版，因为其局部遮挡是消除贴图感的重要证据。

**步骤 4：收集尺度参照**。优先使用有明确型号/尺寸的物体、标准构件或已知地面尺度；其次使用类别宽泛范围；完全不确定则写 `scale_confidence=low`。

**步骤 5：估计空间远近**。可使用单目深度模型、几何透视线、遮挡关系及相对大小联合判断。深度模型一般只提供相对深度；若没有尺度标定，不要把输出直接当米数。

**步骤 6：分析光照**。标出亮部方位、可见投影方向、阴影软硬、局部遮阳、整体色温、是否有强点光源/窗户/天光、光源被遮挡的位置。

**步骤 7：分析相机风格**。检查镜头俯仰、图像行列方向、畸变、边缘锐度、噪声、运动模糊、动态范围、压缩水印、曝光不均匀；将“材质的粗糙”与“相机的模糊”分别建模。

**步骤 8：输出 `scene_profile.json`**：含候选 ROI、遮挡物清单、参考尺寸、允许编辑区、光照置信度及成像统计。

### 7.2 强制人工或规则复核 VLM 输出

VLM 可以建议“这里适合放一个桶”，却可能忽略桶底是否落在悬空废铁上。所有会影响物理有效性的判断，都要由视觉检测、几何规则或人工确认。示例核查问题：

- 物体重心投影是否落在可承载接触区域内？
- 是否存在必须跨过但实际上不能穿透的刚性杆？
- 参考物的真实尺寸是否已知，还是凭类别猜测？
- 光照是否仅能判断“偏漫射”，无法估算真实方位？
- 是否有监控时间戳、证据性标签需要像素锁定？

### 7.3 场景级置信度建议

分开打分而不是给一个“场景清晰度高”总分：`geometry_confidence`、`depth_confidence`、`scale_confidence`、`lighting_confidence`、`occlusion_confidence` 和 `background_integrity_requirement`。任何低置信度维度，应扩大候选区间、增加人工审核或退回补充输入，不得通过输出高置信度的语言掩盖。

## 8. S04–S05：尺度控制的完整落地办法（重点章节）

### 8.1 首先区分四种“大小”

1. **真实三维尺寸**：例如桶的高度、直径、支架宽度（米或毫米）；数据可能缺失。
2. **三维摆放姿态**：同一物体横放、竖放、面向相机时，投影大小不同。
3. **整物体投影轮廓**：物体若无遮挡，本应占据的像素范围。
4. **可见物体范围**：被前景废料挡住后，实际可看见的像素 Mask；可见范围不能反向当作真实物体缩小。

尤其是第 3 与第 4 项必须分离：遮住一个灭火器的 40% 不应让算法推定灭火器“实际尺寸只有 60%”。

### 8.2 分级选择尺度方法，而不是强行统一一个公式

**Level 0：用户直接指定目标像素区域**。在背景原始图上指定旋转包围框 OBB，实用但不证明物理尺寸合理。适合素材排版和先验很强的控制任务。

**Level 1：仅有场景相对参照**。在深度和方向相近时，用参照物投影和已知尺寸比例推断粗略大小：

\[
p_o \approx p_r\,\frac{L_o}{L_r}\frac{Z_r}{Z_o}\frac{\gamma_o}{\gamma_r}
\]

其中 $p$ 为像素投影长度，$L$ 为真实长度，$Z$ 为相机坐标系深度，$\gamma$ 为测量方向和透视引起的投影缩短因子。只有在可比条件下才适用；$Z$ 和 $\gamma$ 没有证据时不能随意设成确定值。

**Level 2：有相机标定、三维物体和放置姿态**。使用针孔相机投影：

\[
\tilde{\mathbf u} \sim K\,[R\mid t] \,\tilde{\mathbf P}, \quad (u,v)=(\tilde u_x/\tilde u_z,\tilde u_y/\tilde u_z)
\]

对全部 3D 顶点投影，求轮廓与 OBB。此法同时约束尺寸、消失点、遮挡优先级，但模型建得错误也会“精确地犯错”。

**Level 3：只有未标定单目图，物体尺寸也未知**。不能唯一恢复绝对尺度，只能给**候选区间**和视觉一致性排序。必须输出 `scale_interval`、`assumptions`、`uncertainty`。不要报告精确米数。

### 8.3 目标 OBB 的设计、约束和坐标系统

推荐统一使用原背景像素坐标下的：

\[
B=(c_x,c_y,w,h,\theta)
\]

其中 `(cx,cy)` 是物体**完整投影**的中心，`w,h` 是沿 OBB 两轴的尺寸，`theta` 是图像平面旋转角；注意它**不能代替三维姿态角**。同时保存归一化值 `(cx/W, cy/H, w/W, h/H)`，若换图尺寸可正确映射。

**步骤 1**：先选**支撑点/接触区域**，再决定物体中心，而非把中心随意放画面正中。

**步骤 2**：根据物品的真实尺寸或合理范围及目标深度，初步给出长宽区间，而不是一个无法校验的数字。

**步骤 3**：考虑朝向投影：面向镜头的长物体看起来会变短，圆筒端面更多可见；给定 OBB 应与可见面的变化协调。

**步骤 4**：检查边界：物体不应遮挡不可碰的监控文字/重要设备，不应无物理原因超出承载平台；允许被其他物体遮住，但完整形体仍要能合理存在。

**步骤 5**：用 3–5 个不同尺度候选试投影或生成轮廓低清预览；先人工/算法选择尺度，再做高成本旧化与高清生成。

**步骤 6**：锁定选中的尺度范围并在后续候选中检验。不能因为下一次生成变漂亮，就默许物体变大一倍。

### 8.4 一个带数字的【示例假设】——不是本次储罐测量值

假设参照钢条长 `0.80 m`，图中同方向有效投影长度 `160 px`；目标物体某方向真实长 `1.20 m`，并根据相机估计参照物深度/目标深度比为 `1.10`，两者方向因子近似相同：

\[
p_o\approx160\times(1.20/0.80)\times1.10=264\text{ px}
\]

这里的 264 px 仅是**特定方向、特定假设**下的投影长度，不是整个目标的包围框宽度，更不是适用于任意物品的固定目标。若相机深度比和方向因子不可信，应生成区间（例如保守上下界）而不是单点。

### 8.5 用检测/分割闭环锁住尺寸

对目标完整轮廓 $B_t$ 与结果中估计的完整轮廓 $B_g$，可采用尺度损失：

\[
L_{scale}=|\ln(w_g/w_t)|+|\ln(h_g/h_t)|
\]

中心位置损失：

\[
L_{center}=\sqrt{(c_{x,g}-c_{x,t})^2+(c_{y,g}-c_{y,t})^2}/\sqrt{W^2+H^2}
\]

再结合关键点误差、旋转角误差、投影轮廓 IoU。**注意**：目标严重被遮挡时，普通物体分割器仅输出可见部分，不能直接将该可见 Mask 的边界框与完整 OBB 比较；应使用可信的完整形体估计，或者只在应可见区域评价。

实践上可先把 `relative width/height error < 10%` 作为**待校准**的实验初值，但具体容许误差取决于类别、姿态、用途和深度不确定性，不能当作行业统一阈值。生成器不支持硬性 OBB 输入时，这些约束只能用于候选拒收/再次生成；不是光写公式就能让模型严格遵守。

### 8.6 复杂堆积场景中的尺度陷阱

- 废钢宽度和长度变化极大，**不能凭“旁边铁条看起来很粗”就认定罐体真实直径**。
- 无标定相机时，近处小物体可能比远处大物体投影更大。
- 部件不能与主体使用不同尺度：压力表、握把、法兰、人孔都必须随同一三维投影变化。
- 影像经过非等比拉伸或镜头畸变时，先纠正或纳入相机模型，否则比例检测会误报。
- 物体被遮住后不能为了露出所有特征而自动扩大；应选择不冲突的摆放位姿或接受合理遮挡。

## 9. S06：从“平面转一下”升级到真实姿态匹配

### 9.1 二维旋转不能代替三维转动

对圆柱储罐，轴线在屏幕上转 15°，并不能告诉我们其绕轴滚转多少。不同滚转会导致顶部人孔、底部支架、侧面管口的位置完全不同。很多“AI感”来源于**不同部件看起来各自处在不同观察角度**。

### 9.2 具体步骤

1. 建立物体局部坐标系：如圆柱轴向为 X、竖直为 Z；固定人孔、接管和支架的局部位置，记录左右端。
2. 在场景中确定三维摆放姿态的候选：位置 $(X,Y,Z)$、偏航 yaw、俯仰 pitch、滚转 roll；数据不足则给离散候选而非伪精确值。
3. 选择与参考图相容的可见面：顶视能看见人孔时，旋转后人孔不应仍保持产品图中的“永远在正上方”。
4. 检查各部件投影一致性：圆筒纵线、法兰边缘、支架的远近关系；箱体检验平行边的消失趋势；曲面物体检验轮廓与高光关系。
5. 对多候选先生成**无材质的轮廓/代理物**预览，确认空间一致后再旧化、加阴影和细节。
6. 将目标姿态传递给可用的条件控制（有 3D 渲染可用几何图，有 ControlNet 类工具可传深度/边缘/姿态控制；若模型不支持则依靠多视图文字约束与结果审核）。

### 9.3 需要额外注意的物体

**灭火器**：阀门手柄、压力表、软管出口位置是非对称的，特别容易出现左右镜像。**方形箱体**：必须检验三个主方向是否共享合理消失点。**弯曲管道**：弯头曲率要与被遮住的部分连续。**柔软物体**：不用刚体姿态概括全部，需要重力下垂和局部接触约束。

## 10. S07：支撑、碰撞、遮挡和接触——消除“贴图感”的核心

### 10.1 将空间交互拆成三种图

1. **遮挡有向图**：`A -> B` 表示 A 位于 B 前面、在重叠区域遮住 B。图对局部像素/部件的适用范围必须注明；复杂卷绕物可能不存在全局单一先后顺序。
2. **接触图**：`touch(A,B, region, confidence)` 表示两个物体在某一接触区域相邻，可能承受法向力、摩擦或共同形成暗部。
3. **支撑/载荷图**：`support(A,B)` 表示 A 承托 B。A 在 B 的图像下面，并不必然意味着 A 承托 B，必须检查局部几何与重力方向。

### 10.2 废铁堆中的接触安排步骤

**步骤 1｜找支撑**：选取至少一组可能承担物品重量的固体区域。例如罐体由两根钢梁/堆料局部接触承担重量；如果支架被遮住，不必强行画出完整支架，但必须有合理的罐体-废钢接触。

**步骤 2｜检查重心与稳定性**：粗略估计物体整体重心，其重力方向投影应与支撑区域相容。对巨大罐体，细铁丝网不应独自承重；柔性薄板被压可合理变形，但要有形变迹象。

**步骤 3｜标记真正前景**：把确实穿过放置 ROI 的钢条、草叶、绳缆、框架边缘分为前景遮挡物；只有可以确认处在物体前方的内容才恢复到物体之上。

**步骤 4｜标记背后区域**：被新物体遮住的废钢应隐去，而不应“半透明地穿过储罐”。无需把背后物体整个删除，只处理可见关系。

**步骤 5｜检查轮廓交点**：在钢条跨过罐体的两个交点，检验其是否连续；薄杆被局部重绘成断杆，会产生新型的贴图感。

**步骤 6｜安排接触暗部**：支撑面与物体接触区域的缝隙一般更暗，阴影形状跟随几何，不是一个整齐的椭圆黑斑。

**步骤 7｜估算投影**：有明显方向光时，投影沿光源反方向；漫射光主导时，重在柔和接触暗部，避免突然出现强硬长阴影。

**步骤 8｜验证穿模**：沿关键钢条/梁截面查是否穿过罐体实体；出现穿模时先调整 3D 姿态或遮挡方案，再重新生成；不要单纯用涂抹遮住穿透点。

### 10.3 接触阴影的工程近似与边界

可构建接触 Mask $M_c$，通过距离变换得到离接触区域的像素距离 $d(x,y)$。简单衰减模型：

\[
S(x,y)=a\,\exp[-d(x,y)^2/(2\sigma^2)]\cdot M_{valid}(x,y)
\]

这里 $a$ 表示局部暗化幅度、$\sigma$ 控制软边，`M_valid` 限制阴影只落在允许受影响的表面。**这只是视觉近似**，其距离场不包含真实光源可见性、表面法向、透射或多重反射；玻璃、镂空结构、方向强光应使用更完整的渲染或模型重绘。

**操作注意**：接触暗部应随接触面积变化。硬金属罐只在少量刚性支点接触，不能涂满一整圈黑色；软袋子压在桌面上，接触区域可更广，投影边缘更柔和。

### 10.4 多物体场景的冲突解决顺序

先处理不可违反的硬约束：实体不可穿透 → 重量与支撑 → 近远遮挡 → 物体身份 → 光照材质 → 局部观感。不能为了画面好看，让承重结构或关键部件消失。如果多物体遮挡图有局部环路，需分解到部件/像素深度层级，而不是强行作全局拓扑排序。

## 11. S08：蒙版体系、前景恢复与严格背景保持

### 11.1 至少维护六个分离的 Mask

| Mask | 定义 | 是否允许生成修改 |
|---|---|---|
| `M_obj_full` | 新物体未被遮挡时的**完整投影** | 仅指示几何，不等于可见区域 |
| `M_fg_occ` | 应位于新物体之前的**原场景前景物** | 不允许破坏其原始形状/纹理 |
| `M_obj_visible` | 真实应露出的新物体部分 | 允许合成/细化 |
| `M_contact` | 接触阴影与局部材料交互范围 | 允许有限定修改 |
| `M_edit` | 生成或修复可编辑区域 | 允许修改 |
| `M_protect` | 必须保持原始像素的区域（叠字等） | 严禁修改 |

可见新物体区域在简单不透明遮挡假设下定义为：`M_obj_visible = M_obj_full AND NOT M_fg_occ`。复杂玻璃/半透明、运动模糊、半透明塑料需额外的 alpha/透射模型，不能直接采用二值减法。

### 11.2 Mask 生成的标准流程

1. 先在目标尺寸背景上确认 `M_obj_full`：来源可为三维投影/人工多边形/轮廓建议，**不能直接用 OBB 当精确轮廓**。
2. 分割场景内重要前景物并审核 `M_fg_occ`；对细杆、铁网，保持其细小结构，避免粗糙羽化把它们抹掉。
3. 使用局部深度关系求交集，得到 `M_obj_visible`，保留物体被遮挡的真实比例。
4. 创建 `M_contact`：沿物体与支撑物交界建立窄区域；在投影需要影响的表面向外延伸，但不能覆盖毫不相关的背景。
5. 合成 `M_edit`：覆盖物体可见范围、适量边缘过渡和阴影交互区；不应未经审查就把整张图设为可编辑。
6. 保护区域优先：`M_edit = M_edit AND NOT M_protect`；若物体目标位置必然与保护区冲突，先调整位置，而不是隐藏冲突。
7. 为每个 Mask 保存文件与语义信息：坐标空间、二值阈值、来源（人工/算法/真实几何）、创建日期和置信度。

### 11.3 前景恢复正确的先后关系

**正确概念**：先得到背景与新物体的合理结合，再将**确认处于前方的原场景纹理**恢复到该物体之上，之后只在接触/边界允许区域做细化。以不透明场景为例：

\[
I_{merged} = (1-M_v)I_{bg}+M_v I_{object}
\]

其中 $M_v=M_{obj\_visible}$。在 `M_fg_occ` 中应选择性保留原背景像素；已被新物体挡在后面的原背景部分则不得在物体前显现。这里的公式只是**分层合成的基线**，它还没有解决新物体的反光、材质、阴影和接缝，因此不能单独当最终产品。

### 11.4 边界过渡需要按原因分类，而不是一律羽化

- **锐利金属边**：轮廓应比较清晰，不应该羽化成透明气体；需要匹配相机 PSF、轻微颜色溢出和抗锯齿。
- **景深/运动模糊边**：物体轮廓与同深度其他物体应具有相近程度的模糊。
- **毛发/织物纤维边**：可需要细丝级分割与 Alpha Matting。
- **透明玻璃边**：应生成折射/反射与透射，而不是把玻璃整体设置为统一 Alpha。
- **堆料接触边**：需要让前景碎片压在物体之前，并形成不规则暗部；接缝过渡通常不止是几个像素的羽化。

### 11.5 如何验证背景确实没有被破坏

如果输出与原图已注册到**完全相同尺寸和像素坐标**，在保护区计算：

\[
D_{bg}=\frac{1}{|P|}\sum_{(x,y)\in P} |I_{out}(x,y)-I_{bg}(x,y)|
\]

严格像素锁定应让未修改区完全一致（可要求逐像素 0 差异）；若输出经过 JPEG 重编码，可能出现微小差异，因此强约束时保存无损 PNG，并在生成后**直接从原图拷回保护像素**。与全图平均差不同，必须只在被明确保护且已注册的像素上判断。

# 第三部分：旧化、光照、生成与多轮修正

## 12. S09：按物品材质生成旧化，而不是给所有物体“刷锈”

### 12.1 材质旧化的三层模型

每个部件建议建立：`base_material`（基材）→ `surface_coating`（涂层/电镀/氧化膜）→ `weathering_layers`（风化、污垢、腐蚀、刮擦、沉积）。旧化变化不仅作用于颜色，还包括粗糙度、表面微形貌、轮廓损伤、反射/透射，以及旧化沿重力和流路的空间分布。

**步骤 1｜明确材质来源与置信度**：实际物品材料已知则按真实材料；未知则选择不容易违背物理规律的保守变化（灰尘、擦痕、失光）。对原本为不锈钢的压力容器，要谨慎区分“表面铁污染导致的褐色痕迹”“腐蚀点”“受损后的锈迹”和“整片碳钢红锈”。

**步骤 2｜按部件分区**：例如灭火器的钢瓶、喷管橡胶、压力表玻璃、塑料握把、金属销分别处理；不能给橡胶软管生成金属锈斑，也不能把玻璃压力表盘涂成完全不透明的铁锈。

**步骤 3｜指定使用历史**：长期露天/海滨盐雾/潮湿室内/高温/工业粉尘/频繁搬运/短期弃置。历史决定污垢形态，不能统一套一个随机噪声。

**步骤 4｜建立环境风化驱动场**：可由接缝、排水路径、接触、局部积水、朝上面、摩擦面和缺口生成不同权重区域。示例：焊缝权重较高、遮挡下方积尘较高、经常被触碰的手柄局部抛光、与地面接触的底面泥污较强。

**步骤 5｜选择局部损伤形态**：氧化、剥落、刮痕、凹陷、孔蚀、发白、褪色、开裂、破损边缘。若损伤改变轮廓，应先修正几何/Mask，再修改材质，不能在原轮廓内凭颜色假装金属已经被撞凹。

**步骤 6｜生成大尺度到小尺度分布**：先决定局部大块锈斑/沾污区域，再添加中尺度细斑和低强度微纹理，避免平均分布、整齐重复、过高频锐利的“滤镜感”。

**步骤 7｜检查重力与暴露方向**：锈水流痕/污泥滴落方向应相对物体实际摆放姿态确定。圆柱翻倒后，“图像向下”不一定等于某个原始部件的局部下方，真实重力方向应根据世界坐标调整。

**步骤 8｜与场景材质统计对齐**：新旧物体的锈迹颜色可参考场景铁锈，但金属母材种类仍应体现差异，不要求 RGB 直方图完全相同。

### 12.2 常见材质旧化动作库

| 材质 | 合理旧化线索 | 需要联动改变的属性 | 特别要避免 |
|---|---|---|---|
| 碳钢/铸铁 | 红褐氧化、鳞片锈、锈坑、油污、局部裸露 | 粗糙度、表面高度、反射降低 | 均匀纯橙色覆盖 |
| 不锈钢 | 水渍、灰尘、茶色斑、局部点蚀、焊缝周边变色 | 拉丝方向保留、局部粗糙度 | 无依据整件厚重红锈 |
| 铝合金 | 失光、灰白氧化膜、点蚀、划痕 | 镜面反射下降、局部凹坑 | 红锈当作铝基材产物 |
| 镀锌钢 | 白锈、镀层剥落、露钢处红褐锈 | 涂层破损与底材对应 | 全面积同等严重红锈 |
| 喷漆钢件 | 脱漆、起泡、划伤、露钢处生锈 | 涂层边缘翘起、基层显露 | 锈斑与破漆位置毫无关系 |
| 铜/黄铜 | 氧化变暗、局部绿锈、指纹 | 颜色、粗糙度、局部反射 | 直接套碳钢红锈模板 |
| 塑料 | 发黄/发白、粉化、应力白痕、划伤、紫外褪色 | 表面粗糙度、颜色梯度 | 金属结壳锈与非真实反光 |
| 橡胶 | 龟裂、积灰、失弹、表面发白 | 法线纹理、微形变 | 像金属一样锈蚀 |
| 木材 | 风化灰化、裂纹、起翘、水渍、霉斑 | 纹理方向、纤维露出、尺寸轻微变形 | 纹理横断年轮方向乱窜 |
| 纸箱/纸板 | 压痕、潮斑、掉色、折角、纤维破口 | 折线、吸水形变、印刷磨损 | 钢板般锐利光泽 |
| 玻璃 | 灰尘、矿物水垢、划痕、裂纹、霉斑 | 透射、折射、反射、厚度边缘 | 无缘由变成全不透明 |
| 布料/绳索 | 灰尘、油污、磨毛、毛边、撕裂 | 褶皱、纤维、张力与重力 | 硬金属式锐利轮廓 |
| 陶瓷 | 污渍、缺口、釉面裂纹、积垢 | 釉面高光、裂缝细节 | 大面积普通金属锈 |

### 12.3 旧化强度配置：全局等级只是起点

建议设 `ageing_level` 为 0–4：0 近新，1 轻微使用，2 明显旧化，3 长期弃置，4 严重破损。每一等级还应包含：各部件锈蚀面积上限、表面粗糙度目标、可见涂层残留率、污垢强度、轮廓损坏权限、关键结构保护规则。**数值必须按材质、尺度和图像分辨率调整**，不要把“3级”自动解释成 70% 面积红锈。

### 12.4 旧化过程中怎样检查“不是贴了一张旧化纹理”

- **几何关联**：锈蚀是否围绕真实焊缝、螺栓、积水处发展，而不是与结构无关。
- **光照关联**：锈面粗糙后高光是否减弱，残存亮金属是否仍有符合环境的反射。
- **深度关联**：凹坑、脱漆边、破损边是否有轻微的明暗层次，而不是纯二维印花。
- **局部统计**：大面积低频褐色斑 + 中小尺度细节，而不是同样大小的斑点整齐铺满。
- **材质分区**：塑料件、玻璃、标签、金属紧固件是否保持材质差异。

## 13. S10：光照、反射、阴影、色彩与相机成像一致性

### 13.1 把画面差异分成六个可以单独修的分量

`lighting_intensity`（亮度）、`lighting_direction`（受光方向）、`color_temperature`（白平衡/环境色）、`material_response`（材质对光的响应）、`shadow_contact`（投影与接触）、`camera_pipeline`（模糊/噪声/压缩/曝光）。不要试图只用一个“整体调色”解决它们。

### 13.2 光照分析的实操顺序

1. **选择对照 ROI**：靠近放置点的相似材质表面，不能仅拿天空和储罐比较；记录它们的平均亮度/中位数/高光与阴影分布。
2. **判断主光方向**：根据已存在物品的亮边、投影方位、纹理凹槽寻找证据；如果多光源或天空漫射居多，则标注“主光方向不确定”。
3. **判断软硬**：背景缺少锐利长阴影时，新物体不应有舞台聚光式硬边投影。
4. **判断环境色**：废料堆周围灰褐和锈红会影响新物体受光下的环境反射；不意味着对所有像素无差别涂褐色。
5. **先修材质再修亮度**：罐体太亮可能因镜面反射和粗糙度错误，不是简单把 RGB 降低就能解决。
6. **分离投影与接触阴影**：投影作用于邻近表面，接触暗部局限在相接区域和小缝隙；两者不能互相代替。
7. **局部重绘交界**：出现黑边、白边或物体像“被镶进场景”时，先核查遮挡和 alpha，再在可编辑窄带处理颜色溢出/阴影。
8. **匹配背景模糊**：目标应该匹配**同深度区域**的模糊与噪点，而不是拿整个画面平均锐度比较。

### 13.3 一些常用公式与适用边界

理想漫反射近似中，表面明暗依赖法线与光源：$I_d\propto\max(0,\mathbf n\cdot\mathbf l)$。但金属、有涂层物体、玻璃等需要反射/透射模型；不能仅靠此式渲染所有材料。空间中同一光源照到的物品亮部方向应协调，**不同材料的亮度绝对值可以不同**。

局部颜色匹配可在 LAB 的 L、a、b 上分别比较物体目标 ROI 与场景相似材料区域的稳健统计（中位数、分位数）。如果直接让物体颜色均值等于整个背景均值，会破坏其应有材质色彩。建议限定最大校正幅度，保留阴影与高光的层次。

### 13.4 监控/CCTV 画风专项（示例）

1. 分析原背景的运动模糊、空间锐度变化、视频压缩边、叠字渲染质量和局部曝光。
2. 避免“8K 超锐微距纹理”“HDR 商拍”之类与 CCTV 画风冲突的生成要求。
3. 输出物体新细节后，匹配目标附近的局部清晰度，不允许物体清晰到每个螺纹都可数，周围钢板却模糊成团。
4. 对模式 B/C，尽量只在物体和可编辑区调色、加模糊/颗粒；不能为匹配画风无故重压缩整张原背景。
5. 叠字区域原位恢复：先在原图复制文字纹理及其边缘；如果文字被物体遮挡的目标设定与原画面冲突，需调整位置或明确允许遮挡，不能让模型编造时间戳。

### 13.5 真实案例的 LAB 参数何时不该照搬

本次 `L*1.20+9` 等数值是针对第二轮生成图偏暗、偏暖的结果而来。其他场景（暖黄色室内、晚霞、夜间钠灯、反光玻璃等）不能无条件复制。对生产管线应：

- 先在与生成对象相同或相近照明条件的局部区域抽样；
- 把照明与材质不确定性纳入决策；
- 在候选校正上计算色彩差异，并由人工/VLM 判断是否破坏材料本色；
- 保存局部改动 Mask，确保保护区不被修改；
- 尽量使用无损格式保存训练素材，另导出 JPEG 预览而非反复有损编码。

## 14. S11：三种生成技术路线怎么选，以及逐步执行

### 14.1 路线 A：参考图驱动的整图联合生成（本次实际采用的类别）

**适用**：场景允许被重新构造，希望快速获得物体与环境的整体融合；强调视觉效果而非背景像素保持。**实施**：

1. 向模型提供目标物品多视图和背景图；规定各输入角色：哪张是身份参考、哪张是必须遵循的场景参照。
2. 描述物品关键部件与目标摆放姿态，给出“主体不要强占整幅画面”的尺度意图。
3. 描述场景中应该发生的交互：下沿被钢条挡住、底部有接触暗部、附近材料重力关系合理。
4. 描述按材质区分的旧化，避免大面积等密度纹理。
5. 描述场景光照及相机画质，不要另加影棚光或背景清洁化。
6. 输出候选并核查外形、相对大小、遮挡和背景变化；若有问题，针对失败类型调整后重试。
7. 选定候选后可做整图/局部校色；必要时承认背景与叠字被生成式重绘。

**优点**：遮挡与接触可共同生成，图像整体性通常好。**硬伤**：背景锁定、准确物件实例结构、尺寸与文字保真较弱，无法保证标注级精确。

### 14.2 路线 B：受控 Inpainting + 背景保护（推荐工业训练样本）

**适用**：原背景应尽量保持不变，允许新增物体及其直接影响区域变化。**实施**：

1. 使用 S05–S07 输出目标完整轮廓/OBB/姿态/接触及遮挡关系。
2. 在原背景上创建 `M_edit`：含新物体可见区域、可变的接触阴影区、需要细化的局部边缘；扣除文字等 `M_protect`。
3. 准备可选的结构控制：深度草图、轮廓图、由多视图/低模生成的姿态参考。模型支持什么输入类型就用什么；不假设某厂家 API 一定提供 3D 控制。
4. 局部生成物体外观，指导其与原图同一空间、局部透视、旧化和光照环境一致。
5. 检查模型有没有擦掉必须位于前方的原场景铁条，必要时把已审核 `M_fg_occ` 的像素从原图恢复。
6. 对接触带局部重绘一次，重点解决支撑接触和黑白边；把没必要修改的原图区域强制恢复。
7. 在完全同分辨率图像上运行受保护背景差分检测，并输出物体 Mask 与编辑 Mask。

**注意**：如果真实物体需要盖住原场景某部分，背景不能在这一部分“逐像素保持可见”。所谓背景保护，应精确定义为**非物体及非交互区域**保持不变，而不是无条件要求所有原像素都可见。

### 14.3 路线 C：代理几何/三维渲染 + 局部生成 + 恢复前景（推荐严格尺度）

**适用**：强调物体尺寸、朝向、零件连接与可验证几何，或者物体参考是结构明确的设备。

1. 用 CAD 或几何原语构建代理模型，单位统一，例如米；校对各主要部件的相对位置。
2. 依据图像与标定/假设建立相机，完成目标位置与姿态的投影；输出深度、法线、语义 Mask、投影轮廓。
3. 用环境估计光照与简单材质生成基本可见结构，不要求此时达到最终照片级质感。
4. 将结构图、原背景、参考物体及旧化描述输入支持条件控制的生成编辑器，使其细化表面纹理而**尽量不改变投影轮廓**。
5. 通过遮挡蒙版恢复现场前景对象，再根据物理支撑与光照修复接触阴影。
6. 锁定保护区、检验几何误差、重新生成有问题的局部区域；将精确几何 Mask 作为标注主依据，而非使用生成模型自由分割作为真值。

**注意**：需要 CAD、相机或可容忍的标定误差；构造错误的 3D 模型会使图像虽然“精确”，但与原物品不符。

### 14.4 路线对比及选择规则

| 需求 | 推荐方法 | 不该作出的承诺 |
|---|---|---|
| 只需概念图、样例演示 | A | 背景逐像素无变化 |
| 场景是现有监控画面、需物体自然出现 | B | 在不编辑任何背景像素的情况下创造完整投影与接触 |
| 设备结构必须准确、支持多视角 | C（再加 B 的局部重绘） | 六视图即等同真实 CAD |
| 高度复杂的软体、透明体 | B/C + 专门材料处理 | 通用二值蒙版可以搞定折射/柔性变形 |
| 多件物品相互遮挡 | B/C 的联合优化 | 每件独立生成后简单排序一定正确 |

## 15. S11：提示词如何写得可验证——含通用模板与专用模板

### 15.1 每次生成提示词都应有固定字段

推荐结构 `Reference roles → Fixed identity → Placement → Scale → Geometry → Occlusion → Contact → Ageing → Lighting → Camera style → Protected areas → Prohibitions`。先列硬约束，再列美术细节；不要在一句话里同时要求“完整展示所有细节”和“深埋废料、自然遮挡”，这两者可能冲突。

### 15.2 通用正向模板（把中括号替换成真实配置）

> **图像 A** 为 `[物品ID/多视图]` 的结构参考，**图像 B** 为必须遵循的 `[场景ID]`。在图像 B 的 `[目标区域]` 中生成一件或多件 `[物品名称]`，保持 `[主体形状/关键部件数量和方向/连接关系]` 不变。物体的完整投影应位于 `[原图像素/归一化 OBB + 容差]`，朝向为 `[姿态描述/结构参考]`，不为展示全部部件而放大。它由 `[承重对象]` 在 `[接触区域]` 支撑，`[前景物]` 自然遮住 `[物品区域]`，它又遮挡 `[背景物]`。在 `[接触点]` 生成合理的局部暗部，并使投影和高光遵从 `[场景光照线索]`。材质为 `[基材/涂层]`，旧化表现 `[按部件的污渍、腐蚀、划伤、褪色与环境暴露规律]`，绝非整件均匀覆盖一层纹理。相机风格匹配 `[锐度、噪声、压缩、白平衡]`。仅修改 `[M_edit]`，保护 `[M_protect]`。最终画面必须让物体真实占据三维空间而不是平面贴上去。

### 15.3 通用负向约束模板

> 物体放大、尺寸漂移、主体变形、关键部件缺失、镜像错误、额外接口、零件悬空、穿模、没有支撑、独立硬黑影、夸张舞台灯光、白边、黑边、半透明贴纸、边缘像被抠图、HDR 过锐、背景被改写、重复规则锈斑、与材质不符的红锈、监控叠字被改写、画面变成商业商品摄影。

### 15.4 Prompt 无法保证什么

如果模型没有 `target_mask`、`bounding_box`、`depth_control` 等输入接口，文本中的精确坐标可能被忽略；“严格保持原场景每个像素”也不能靠文字约束保证。正确操作是优先利用模型公开支持的**图像/Mask/控制条件**，并在输出端用程序验收，不合格就淘汰或局部修复。不同提供方参数（编辑强度、参考权重、seed 等）能力不完全相同，必须查 API 文档并将实际调用参数写入日志；本文不冒用任何厂商内部配置。

### 15.5 储罐/灭火器/玻璃的结构加句

- **储罐**：罐体长轴贯穿两个弧形封头，检修口和多个法兰与曲面关系合理，底部支承允许被废铁局部遮挡，但不能消失成纯圆柱。
- **灭火器**：罐口的阀门、握把、保险销、压力表与喷管有连续连接关系，软管随重力自然弯曲，不能出现握把朝向与参考图相反的镜像错误。
- **玻璃器皿**：保留玻璃厚度和近边缘折射/反射，内部与后方背景仍可透见并产生合理畸变，污垢主要改变透光和局部粗糙度，不是变成不透明铁制品。

## 16. S12–S14：候选生成、分类评分、修复、最终成像

### 16.1 不建议“一次生成直接交付”

**步骤 1**：固定任务配置，第一批生成 2–4 个低成本候选（可用具体模型支持的低分辨率模式），记录每个候选 ID 和实际参数；这是建议数量，并非本次实际迭代次数。目的不是盲目多抽样，而是判断放置策略可否成立。

**步骤 2**：先检硬约束：物品类别与部件、目标边界大小、位置、前后遮挡、能否承重、原场景是否被破坏。任一关键项失败则不进入美化步骤。

**步骤 3**：再检软约束：色差、亮暗、锐度、污迹分布、噪声和局部边界自然度。允许选择最有潜力候选，但不能用后处理掩盖结构性错误。

**步骤 4**：为每个不合格项生成**结构化反馈**，例如：`{error_type: "IDENTITY_DRIFT", part: "fire_extinguisher_handle", action: "restore_asymmetric_handle_orientation"}`。

**步骤 5**：按问题责任层修正——尺度回 S05，姿态回 S06，遮挡回 S07，Mask 回 S08，旧化回 S09，亮度阴影回 S10，细部生成回 S11；不要全交给一个笼统的“看起来不自然，请重做”。

**步骤 6**：对具备局部编辑接口的模型只重绘问题区域，保留已合格区域；若模型只能整图生成，则重新生成并重新执行所有验收。

**步骤 7**：达到指定质量门槛或预算上限才停止。任何“未达标但用完预算”的图应标记为 `REJECTED / REVIEW_REQUIRED`，而不是自动通过。

### 16.2 生成失败的根因与修复策略

| 症状 | 首先检查 | 根因推测 | 实施修复 |
|---|---|---|---|
| 物体明显过大 | OBB/参照尺寸/物体深度 | 主体显著性驱动放大 | 固定 Mask/OBB、低清候选尺度筛选 |
| 物体太小看不清 | 放置深度及预期任务 | 参考物远/透视误判 | 检查相机与目标深度，不盲目提高清晰度 |
| 像漂浮 | 接触图/重心/底缘间隙 | 缺少真实支撑 | 改放置位置，增加接触/局部遮挡 |
| 像贴纸 | 遮挡/光照/锐度/边缘 | 只有二维覆盖 | 前景恢复、局部阴影及边界重绘 |
| 锈像印花 | 锈区分布/粗糙度 | 重复贴图、旧化与结构无关 | 按焊缝/接缝和重力分区重新旧化 |
| 零件左右反了 | 部件关系/多视图 | 发生镜像/姿态不一致 | 引入非对称关键点、姿态硬约束 |
| 背景废铁消失 | `M_edit` 太大/全图重绘 | 生成器重构背景 | 使用 B/C 路线并恢复保护区 |
| 白边黑边 | Alpha/颜色预乘/边缘滤波 | 抠图或模型修补接缝 | 纠正蒙版、局部环境色溢出与过渡 |
| 阴影方向错 | 光源估计 | 默认舞台灯光 | 约束主光/删掉错误投影并局部重建 |
| 物体过清晰 | 局部锐度与压缩 | 高分辨率生成风格 | 仅在新物体上匹配同深度 PSF/噪点 |
| 人孔/阀门变形 | 多视图身份约束 | 复杂部件被模型简化 | 结构渲染/关键点约束/局部重绘 |
| 文字被改写 | 保护层没有锁 | 图像模型重绘文字 | 文字 Mask 原图恢复并人工核对 |

### 16.3 统一后处理的正确操作次序

1. 修几何（尺寸、位置、姿态），因为颜色调整修不了这类问题。
2. 修遮挡和接触（真正去贴图感的关键），明确哪些像素应来自原图。
3. 修材质响应和光照方向，再做局部亮度/色度匹配。
4. 修边缘成像：PSF/抗锯齿/局部噪点，避免物体边缘被模糊成透明。
5. 对严格背景模式恢复 `M_protect` 及不在 `M_edit` 内的原图像素。
6. 最后做文字一致性检查、标注输出和无损导出；JPEG 只用于确需监控风格的展示版本。

### 16.4 多轮生成日志记录什么

每轮至少写：`candidate_id`、源文件哈希、模型/版本（可得时）、API 名称、输入尺寸、输出尺寸、显式 Prompt、实际提交的控制参数、蒙版 ID、目标 OBB、失败项、分数、选择/拒绝原因、修改说明。模型内部不可见的真实采样器、随机状态和隐藏扩写不应编造；可以明确写 `not_exposed`。

# 第四部分：客观验收、具体物品作业配方与场景适配

## 17. S15：质量验收如何量化和人工复核

### 17.1 先判硬约束，再计算综合质量

建议把检查结果分为 `HARD_FAIL / SOFT_WARN / PASS / UNKNOWN`。硬约束包括：关键结构方向正确、尺寸/目标 ROI 在容忍区间、受保护像素不变、不发生明显穿模/漂浮、物体数量正确、遮挡关系一致。**硬失败绝不能被高审美分数平均抵消**。

### 17.2 可验证指标及适用条件

| 指标 | 定义/计算方式 | 适用条件 | 常见误用 |
|---|---|---|---|
| `bbox_center_error` | 生成 OBB 中心相对目标中心的距离 / 对角线 | 同坐标系、有可靠生成检测 | 将可见 bbox 与完整 bbox 混用 |
| `scale_log_error` | `abs(log(wg/wt))+abs(log(hg/ht))` | 姿态近似一致、完整轮廓可估 | 旋转/遮挡后直接比较 AABB |
| `mask_IoU` | `intersection/union` | 有真实或高质量目标 mask | 把分割器猜测值当真值 |
| `keypoint_error` | 关键点投影距离、归一化到局部尺寸 | 关键件定位可靠 | 忽略左右方向造成误配 |
| `background_absdiff` | 保护区内原图与结果逐像素差异 | 同尺寸、同坐标、未 JPEG 重编码 | 在不同尺寸图上直接算 |
| `contact_gap` | 支撑点与目标轮廓的局部间隙 | 已定义真实接触区域 | 以低清黑影误认为真实接触 |
| `occlusion_consistency` | 与前后关系预期相符的区域占比 | 遮挡图已审核 | 只看“遮住多少”不看“谁遮谁” |
| `local_delta_E` | 对比环境相关同材质/同光照区域的色差 | ROI 可比，经过色彩管理 | 要求不同材质绝对颜色相同 |
| `sharpness_ratio` | 与同深度邻域高频能量比 | 局部内容频谱可比 | 用单一 Laplacian 方差评价真实感 |
| `identity_score` | VLM/关键点/检测模型检查部件 | 需配人工抽检 | VLM 自我评价被当作唯一依据 |
| `human_realism` | 盲测人员判断是否突兀、根因标注 | 明确规则并随机呈现 | 把审美偏好当几何真值 |

### 17.3 如何真正量化“贴图感”

建议拆成五组原因而不是发明一个难解释的单一分数：

1. **边缘异常**：物体边缘是否出现不自然亮/暗晕圈；对边缘带计算局部梯度跳变和色差（注意真实物体边界本身就应有真实梯度）。
2. **前景一致性**：穿过目标 ROI 的原始钢条/树枝/绳索是否连贯，遮挡次序是否合理。
3. **接触一致性**：物体与承载面在预期接触位置是否有几何连续性、接触阴影及合理的支点。
4. **光度一致性**：对相近深度、相近材质、相似照明环境的局部区域比较亮度分布、反光方向与阴影软硬。
5. **成像一致性**：清晰度、噪声、锐化边缘和压缩块是否和同深度背景相符。

把上述诊断作为反馈原因列表输出给生成器，而非只报告“真实感 82 分”。

### 17.4 评分权重只是可校准实验参数

可定义：

\[
L = \lambda_g L_{geometry}+\lambda_o L_{occlusion}+\lambda_c L_{contact}+\lambda_l L_{lighting}+\lambda_a L_{appearance}+\lambda_b L_{background}
\]

其中权重随用途变化：展示场景可提高感知质量权重；工业检测数据集要优先保证背景锁定、Mask 准确和类别结构真实性。对不同尺度指标需先正规化，**不能把像素差、颜色差和 VLM 分数直接相加**。建议在少量有人类标注的样本上调校权重，再在独立样本上验证；绝不声称该公式本身能够训练任何生成模型。

### 17.5 人工验收的三次放大检查

- **缩略图全局看**：判断物体是否过大/过小、摆放是否突兀、主光是否相反、画面风格是否割裂。
- **100% 像素看接触**：重点看接触点、前景杆件交叉处、封头和法兰边缘、物体与背景过渡是否有白边/错误模糊。
- **200% 局部看身份**：逐一核对人孔数量、阀门方向、手柄、喷嘴、文字、紧固件连接。高倍率只是查错工具，不能要求低像素的监控原图呈现原本不存在的细节。

### 17.6 验收报告建议的输出格式

```json
{
  "sample_id": "demo_case_001",
  "status": "REVIEW_REQUIRED",
  "hard_checks": {
    "identity": "PASS",
    "scale": "UNKNOWN",
    "support": "PASS",
    "background_lock": "NOT_APPLICABLE"
  },
  "soft_checks": {
    "local_lighting": "SOFT_WARN",
    "sharpness_match": "PASS"
  },
  "observed_issues": [
    {"type": "LIGHTING_MISMATCH", "roi": [700, 200, 1050, 500],
     "evidence": "目标罐体局部仍比相邻废钢偏亮"}
  ],
  "requires_manual_review": true
}
```

该 JSON 是数据结构示例；其值不是已经对当前案例运行检测模型得出的统计评分。

## 18. 多种物品的逐步实施配方（所有小节均为【建议实施示例】）

以下每个例子都遵循一个相同的“八问”模板：**物品是什么 → 真实尺寸从何来 → 在哪里放 → 如何受力 → 谁遮谁 → 如何旧化 → 光照如何匹配 → 怎么验收**。数值需要从实际输入推断，不提供跨场景不变的“占画面百分比”。

### 18.1 A 类：卧式储罐/压力容器 + 废铁堆

**1. 身份建模**：将筒身、两封头、人孔、接管、双支座作为独立结构部件；记录哪一侧有人孔和法兰，防止左右镜像。**2. 尺度**：有铭牌/型号/图纸时用实际长度、直径；只有六视图就记录长径比的视觉估计范围，按背景废钢支撑范围选择候选 OBB。**3. 姿态**：设定罐体在废料上横卧、倾斜或轻微侧翻；人孔方向随三维滚转变化。**4. 接触**：至少核查两处相距一定距离的承重点或一片可信支撑区，不能让一片弯曲铁网单独支撑整个大型容器。**5. 遮挡**：近前的条状钢板遮住部分支架/筒身下沿；背后碎铁被筒身挡住。**6. 旧化**：残余灰银/氧化膜与局部锈、水渍、积灰混合，焊缝/连接口更脏；不默认整个不锈钢罐厚重红锈。**7. 光照**：保留废铁堆环境漫射感，罐体高光弱且广，接触区暗部自然。**8. 验收**：检查长径比、人孔和接口数量、支撑、右近端封头透视以及前景钢条连续性。若背景需像素锁定，采用 B/C 路线；本次真实案例采用的是 A 路线。

### 18.2 B 类：灭火器 + 工厂废料堆/仓库

**1. 身份**：瓶体、顶部提把与压把、保险销、压力表、阀体、软管、喷嘴、底圈分成部件；尤其给压把/软管出口定义左/右非对称关键点。**2. 尺度**：依据具体型号的容量和已知外形尺寸，绝不能以一个通用“灭火器高度”替代全部型号；型号未知时用不同容量的尺度候选。**3. 姿态**：竖立时底圈落地，横倒时罐侧面与地面/废铁接触；握把随罐体旋转，软管受重力下垂。**4. 物理**：保持阀体机械连接，不允许软管漂浮或喷嘴插入瓶壁。**5. 遮挡**：前景铁条可遮罐体部分，但压力表和提把若为关键检测目标，选能露出主要识别特征的位置。**6. 旧化**：红/黄喷漆褪色、划伤脱漆、局部碳钢锈；橡胶软管老化而非生锈，表盘玻璃保留反光。**7. 光照**：金属阀体与漆面反射不同；局部接触阴影紧贴底圈。**8. 验收**：做左右方向对照，检查手柄朝向、软管连接、压力表完整、阀体比例；一旦镜像错必须局部重绘，不能仅校色修复。

### 18.3 C 类：立式钢瓶/气瓶 + 室内仓库

**1. 身份**：瓶肩、瓶颈、阀门、防护帽、筒体、底座、铭牌；禁止凭空增加第二个阀门。**2. 尺度**：型号及尺寸来自铭牌或标准规格；若无，记录宽高比例和不确定性。**3. 放置**：竖放时底座应与地面完整接触，若需要靠墙/捆绑，绳索应合理固定；横倒时接触区域沿筒体/保护圈改变。**4. 受力**：不允许悬空靠在墙面，倾倒位置的落点必须真实。**5. 遮挡**：仓库货架腿可能遮住瓶侧；前后顺序依据地面重合点判断。**6. 旧化**：油漆磨损、局部露底、阀门积尘，旧化程度与使用/检验状态相符。**7. 光照**：仓库荧光/天窗可能形成顶部冷白长形反射，地面投影柔硬由原图决定。**8. 验收**：阀门方向、瓶口连通、底部接触、同场景其他瓶的尺度一致。安全提示：图像合成不表示气瓶现实摆放已符合安全规范。

### 18.4 D 类：直管、弯头、法兰管 + 施工场地/废管堆

**1. 身份**：管径、壁厚、弯曲半径、端面开口、法兰螺孔、焊缝、长度分布。**2. 尺度**：由管径标准/法兰规格优先约束，其次使用参照物；图像开口椭圆长短轴会随朝向变化。**3. 姿态**：靠轴线端点、弯曲中心线和三维滚转表示，不能只用整块 AABB。**4. 支撑**：管件可与下方管道形成线接触/局部点接触；斜放时注意不能在堆料里无支撑穿梭。**5. 遮挡**：管道会多次出现在其他钢管的前后，必须逐段建立相对深度，不应假设“整条管永远在最上面”。**6. 旧化**：碳钢锈蚀沿积水和下表面不同分布，法兰焊口附近更脏；管内壁旧化与外壁可不同。**7. 光照**：管身圆形截面的明暗条带沿轴向延续，法兰面方向正确。**8. 验收**：管径不能在同深度位置无理由突变，管口不能像黑色贴纸，弯头必须几何连续。

### 18.5 E 类：铁桶、化工桶、涂料罐 + 废料堆/车间

**1. 身份**：圆筒、卷边、桶盖、塞口/把手、焊缝；明确是开口桶、密封桶还是塑料桶。**2. 尺度**：按型号容量推定范围；不能把小涂料罐画成大型油桶。**3. 姿态**：倒放时开口要跟随真实透视，立放时底圈与地面接触。**4. 受力**：空桶被压可凹陷，有液体时应维持合理形状和倾斜风险。**5. 遮挡**：重叠铁条自然挡部分桶身，背后废料不穿透桶壁。**6. 旧化**：喷漆剥落、折痕处锈蚀、桶底积污；印刷文字若原物体身份依赖它，尽量保留或用原始纹理/矢量复原，不让模型随意改字。**7. 光照**：锈面降低光泽，桶盖内外亮度符合开口深度。**8. 验收**：口径、卷边、缺口、桶身凹陷和接触位置是否一致。

### 18.6 F 类：电机、电控箱、工业零部件 + 机械维修区

**1. 身份**：箱体长宽高、轴伸、法兰孔、散热片、接线盒、铭牌；记录哪些特征是功能性且不可删。**2. 尺度**：优先用型号图纸与安装孔距，未知则用同场景工具作宽范围参照。**3. 姿态**：箱体平面必须有一致消失点；圆轴必须与轴承座共轴。**4. 受力**：电机通常以壳体或脚座接触，若压在软塑料或布上应出现压痕/褶皱。**5. 遮挡**：电缆可穿过局部前景，但接口连续；工具压在电机之上时应给出支撑/阴影。**6. 旧化**：散热片积尘、边角碰伤、螺栓锈、铭牌发暗，绝不把电机散热片涂成模糊泥团而失去结构。**7. 光照**：高低起伏散热片产生连续的细阴影，塑料接线盒与金属壳体反光不同。**8. 验收**：轴同心、孔位、散热片规律、底脚支撑与箱体透视。

### 18.7 G 类：扳手、铁铲、异形金属件 + 杂物堆

**1. 身份**：扳手开口角、齿形、孔位、铲头与柄连接、弯曲曲率；尽量用关键点或多边形轮廓。**2. 尺度**：小工具适合用附近螺丝/砖块/手柄直径约束；背景缺参照时只提供大致类别范围。**3. 姿态**：杆状部分朝向与投影缩短一致；薄板边缘出现时应变窄。**4. 接触**：工具两端可分别接触不同废料，不能仅一端无支撑悬着。**5. 遮挡**：被钢丝网局部遮住时保留工具连续轮廓，不把杆件随机截断。**6. 旧化**：局部冲击磨亮、手握区油污、锈斑沿凹槽聚集，切削刃可能比其他地方亮。**7. 光照**：薄金属边缘反光随法线变化。**8. 验收**：开口/刃口结构与原参考一致，异形件不因旧化被模型简化成普通铁条。

### 18.8 H 类：塑料水桶/油壶/容器 + 室外角落

**1. 身份**：瓶身高度/截面、把手孔、瓶盖、出液嘴、压制筋；把手必须和桶壁连接。**2. 尺度**：根据容量标识与同场景砖块/台阶/工具估计，而不是借用金属桶尺寸。**3. 姿态**：透明或半透明塑料应看见一定透光；空壶可在受力下变形。**4. 受力**：轻物体可被一小块砖支撑，但有液体时重心和液位应合理。**5. 遮挡**：草叶/电线可部分挡住桶身，同时新容器遮挡后方地面。**6. 旧化**：紫外褪色、发白、刮伤、泥污、局部应力裂纹；**绝不添加碳钢红锈**，除非确有金属配件。**7. 光照**：塑料的广泛高光、透光与环境色协调。**8. 验收**：把手形状、出液嘴连接和透光关系合理。

### 18.9 I 类：玻璃瓶/罐 + 室内桌面/地面

**1. 身份**：瓶口、颈部、壁厚、底部、盖、刻度/标签；注意内外轮廓。**2. 尺度**：与桌面餐具、书籍或可靠参照比较；缺尺寸时以常见规格作有标记的估计。**3. 姿态**：底面支撑、倾倒时瓶身与台面局部接触；液位必须与重力方向一致。**4. 受力**：玻璃落在硬表面通常不出现大面积柔软压痕。**5. 遮挡**：透明瓶能看见扭曲的后景，不是“前景遮挡物简单覆盖”即可完成。**6. 旧化**：水垢、污渍、灰尘、轻微划痕，可局部裂纹但不能不允许时随意破碎。**7. 光照**：边缘 Fresnel 反射、折射变形、接触焦散可能存在但不必强求每张照片都可见；投影不应是整块不透明黑影。**8. 验收**：后景透射、折射方向、瓶底接触与真实环境光一致。

### 18.10 J 类：木箱/纸箱 + 仓库/雨后室外

**1. 身份**：边框、板片、箱盖、钉子、印刷、瓦楞折线；区分实木、胶合板、纸板。**2. 尺度**：运输箱规格/货架尺寸/地面铺砖参照。**3. 姿态**：三组箱体棱边必须遵循同一个透视体系。**4. 受力**：木箱通常保持刚性但会裂开，纸箱受压可塌陷；重物压在纸箱上却毫无折痕通常不自然。**5. 遮挡**：仓库货架柱、包装带、地面杂物按前后关系遮挡箱体。**6. 旧化**：木材纤维方向上的裂纹、水渍、漆膜剥落；纸箱折角破损、受潮变软、印刷褪色，**不是金属锈迹**。**7. 光照**：木板哑光为主，胶带反光更强。**8. 验收**：透视、接缝、印刷和变形与场景用途合理。

### 18.11 K 类：布袋、帆布、软管、绳索 + 户外废料/车厢

**1. 身份**：主要轮廓、缝线、开口、提手、绑扎点、材质纹理。**2. 尺度**：通过支撑面或相邻物件推定；布料非刚体，不宜只用一套刚性 OBB 控制最终轮廓。**3. 姿态**：优先约束固定点/接触点、重力下垂及布料张力，再让局部褶皱自由生成。**4. 受力**：软袋压在铁条上应出现压陷和跨越形变；绳索缠绕时沿曲面贴合。**5. 遮挡**：布料可盖住底下零件，底部也会被局部碎件挡住。**6. 旧化**：沾污、织物磨毛、褪色、油斑、边缘破口；除非有金属扣具，**不生红锈**。**7. 光照**：褶皱阴影必须沿张力与弯折产生，不能依赖规则阴影贴花。**8. 验收**：与接触物形变协调，不出现悬空拉直或布料无厚度的问题。

### 18.12 物品配方如何转为自动化规则

上面不是 11 套完全独立代码，而是对同一“部件树 + 材质部件表 + 尺度与姿态 + 支撑遮挡图 + 成像风格”数据结构配置不同规则。例如灭火器增加 `handle_orientation_constraint`；玻璃增加 `transmission_refraction`；织物启用 `deformable_contact`；储罐和钢瓶加强 `rigid_support_check`。这意味着系统可以增加新类别，而不是每来一个物品就重写整个流程。

## 19. 不同背景场景的调整步骤

### 19.1 废铁堆/混合垃圾堆

- **风险**：碎件几何复杂、深度难估、参照尺寸不可靠，物体容易漂浮或被整堆重绘。
- **操作**：先标记可支撑的局部钢梁/板片，再构建前景碎件 Mask；大件物品需要明确支撑路径，允许下缘被小碎件局部遮挡；材质以灰尘/锈蚀/油污混合；光照常需匹配环境漫射。
- **特别验收**：前景细杆是否断裂、物体下面是否真的有承重件、模型是否随意清理废料堆。

### 19.2 室内仓库/货架区域

- **风险**：货架直线透视十分明显、物体易与架层穿模，光源多且色温复杂。
- **操作**：使用地面/货架/墙面消失线约束箱体或桶体；明确物体属于货架第几层、前后栏杆哪个在前；阴影跟随顶灯与货架遮挡；标牌/地面线保持不变。
- **特别验收**：支撑面深度一致、货架横杆连续、物体与栏杆层级正确。

### 19.3 厂房设备旁/维修平台

- **风险**：原本高精度的机械连接会被模型简化，背景设备误改成新件。
- **操作**：加强轴孔同心、零件尺寸与安装关系；选择靠近设备的参照孔距/工具来估计大小；用窄 Mask 把新增件嵌入局部空间，恢复原设备上的标签和纹理。
- **特别验收**：管路连接正确、不凭空添加维修焊缝/螺栓。

### 19.4 室外地面/道路/工地

- **风险**：太阳方向与投影明显、地面纹理有真实透视尺度，放大错误容易暴露。
- **操作**：先确定地平面及接触点，利用地砖/标线/已知物体进行透视尺度估计；按太阳方位约束投影；新物品触地位置可有少量尘土/泥痕，但严禁无依据改动路面标识。
- **特别验收**：透视、接地阴影、远近尺度、环境亮度。

### 19.5 潮湿/雨后/积水区域

- **风险**：只加湿润高光，忘记水膜、排水方向和接触泥水。
- **操作**：将干湿状态作为场景层；物体迎雨面、积水凹陷、流痕及接触地面湿痕分别约束；如果可见镜面水洼，可要求合理倒影，但没有水就不能凭空生成大倒影。
- **特别验收**：湿润方向是否一致、倒影/接触反射是否物理上可见。

### 19.6 夜间路灯/室内暖灯

- **风险**：全局套用白天灰冷校色导致颜色不自然，强投影方向与物体亮边不一致。
- **操作**：识别多个局部光源，分区进行亮度/色温匹配；物体高光可能偏黄或偏蓝，不能为了“看起来中性”强行去掉环境照明；阴影方向应与灯位一致，必要时使用 3D 渲染。
- **特别验收**：局部照明渐变、反射色与投影方位。

### 19.7 监控照片/低清视频帧

- **风险**：新物体过锐、噪声结构不同、叠字被篡改、全图缩放导致原背景无法逐像素比较。
- **操作**：保留原帧及元数据；区域级匹配模糊、压缩和色彩；叠字单独原样恢复。若用于合成训练数据或演示，清晰标注“合成/模拟”，不要宣称监控记录了真实新增物品。
- **特别验收**：相机角度、锐度梯度、压缩风格、叠字与原图一致性。

### 19.8 透明背景物/镜面房间/水族箱等特殊环境

- **风险**：简单 Mask 与明暗匹配不够，光路和可视后景具有重要作用。
- **操作**：另建透射/折射/反射模型；优先选具备物理材质控制能力的渲染器，再交由局部生成匹配风格；让 VLM 只做语义审核，避免假装能够给出精确折射率或光源参数。
- **特别验收**：边缘折射、镜面中的对应物体、透明体后方的物体是否扭曲得合理。

## 20. 多个物品同时加入时，为什么不能逐个独立生成

### 20.1 同时有三个物品的例子

假设废铁堆中要加入：A 卧式储罐、B 灭火器、C 锈管。不能先生成大储罐并锁死，再在剩余空间放灭火器而完全不检查它们的前后关系。正确做法：

1. **联合选点**：根据容量、尺寸与遮挡预算生成多个放置候选；明确大物件占用支撑区、其他物品是否被阻挡。
2. **按实际空间构造关系**：例如 A 在底层，C 从 A 上方经过，B 斜靠在 A 与前景废料之间；若物理重量不允许，将关系调整为 A 与 C 分别由废钢支撑。
3. **统一相机与光照**：A、B、C 不能每件都像单独镜头拍摄；它们共享相机、场景尺度与主光。
4. **全局材质时效**：它们可以有不同年限、不同锈蚀程度，但同一场景的灰尘、潮湿、反射和光照应一致。
5. **联合遮挡求解**：创建物体-物体、物体-背景的局部层级关系；每个交界面都有对应 Mask。
6. **优先渲染/生成大体量支撑者**，再生成遮挡物和小物件（如果使用逐层编辑）；最终对所有交界进行联合精修。
7. **全局验收**：分别核查每一件的身份和大小，再检查相互遮挡、重心和画面密度。总物品数、目标类别比例和遮挡程度应符合数据集配置。

### 20.2 遮挡顺序示例

```text
background_scrap_17 → tank_A         # 前景废铁条遮储罐
pipe_C → tank_A                     # 管子位于储罐前方
extinguisher_B → background_scrap_09 # 灭火器遮住后方板件
background_scrap_04 → extinguisher_B # 另一块前景板挡灭火器下沿
```

**注意**：这是假设场景关系，不是对已有照片实际分割后的输出。真正系统中还要指明局部交叠区域，避免一条管子在不同位置穿插产生“全局顺序环路”。

### 20.3 多件物品的配额和拒收

给每件设：`min_visibility`（任务要求至少可见多少目标关键信息）、`max_occlusion`、`bbox_interval`、`identity_priority`、`allowed_pose`。对检测训练样本，允许出现难样本但要显式标注遮挡；若一件物品完全被另一件遮住、视觉上不可检，则不能不加说明地把它当正常可见正例。

## 21. 适用于不同生成/VLM 模型的自动化软件架构

### 21.1 不把“模型会自己理解”当系统接口

建议采用以下组件化划分：

| 模块 | 责任 | 核心输入 | 核心输出 | 不负责什么 |
|---|---|---|---|---|
| AssetRegistry | 保存素材、版本、哈希和许可 | 原始图/元数据 | 只读文件索引 | 不判断图片真实感 |
| ObjectParser | 部件树、多视图匹配、材质/尺寸置信度 | 物体参考图 | `object_profile` | 不臆造缺失真实尺寸 |
| SceneParser | 支撑面、ROI、参照物、光照、遮挡候选 | 背景图 | `scene_profile` | 不宣称单图绝对深度真值 |
| PlacementSolver | 尺度区间、目标 OBB、姿态候选 | 两个 profile | `placement_candidates` | 不负责最终纹理 |
| InteractionSolver | 遮挡图、支撑接触图、合法性检查 | 放置候选/场景实例 | `interaction_plan` | 不把光照当几何 |
| MaskBuilder | 可见物、前景遮挡、接触、编辑、保护 Mask | 几何/分割/深度 | PNG/数组 | 不生成物品身份 |
| MaterialPlanner | 物品分部件旧化 | 材质/环境/年龄 | `ageing_plan` | 不随意改变刚性结构 |
| GeneratorAdapter | 把通用计划转换成某提供方请求 | 图/Mask/Prompt/控制 | 生成候选与调用日志 | 不替代结果验收 |
| LocalRefiner | 局部生成、接触边界、反光/阴影修补 | 候选/局部 ROI | 修正候选 | 不擅自改全图 |
| ImageHarmonizer | ROI 色彩、模糊、噪声、压缩适配 | 候选/目标 ROI | 统一成像结果 | 不修几何穿模 |
| QualityGate | 几何/身份/遮挡/背景/色彩验收 | 候选/期望约束 | 报告/反馈 | 不凭单一 VLM 分数通过 |
| Exporter | 打包图片、Mask、标签、来源 | 已审核记录 | 数据集/报告 | 不擦除合成来源 |

### 21.3 生成适配器的基本接口

```python
class GeneratorAdapter:
    def capabilities(self) -> dict:
        """声明支持的输入：multi_images/mask/depth/seed/size 等。"""
        raise NotImplementedError

    def generate(self, *, object_refs, scene_ref, prompt,
                 negative_prompt=None, edit_mask=None,
                 pose_control=None, depth_control=None,
                 output_size=None, model_options=None) -> dict:
        """返回输出路径、实际提交参数、真实响应标识及耗时。"""
        raise NotImplementedError
```

**适配原则**：如果某模型不支持 `edit_mask`，就不要假装传入后生效；应退回路线 A，并在质量报告中将 `background_lock=NOT_GUARANTEED`，或更换支持编辑蒙版的模型。对于 Wan、Seedream 或其他模型，优先用实际可用的 API 文档验证可接受分辨率、最大图片数量、编辑能力、异步回调和费用；不要固定写死版本无关的不存在参数。

### 21.4 自动选择路线的决策树

```text
需要背景逐像素不变吗？
 ├─ 是 → 有精确物体尺寸与相机/3D 吗？
 │        ├─ 有 → C：投影几何 + 局部生成 + 像素恢复
 │        └─ 无 → B：候选尺度区间 + 局部生成 + 人审
 └─ 否 → 物品是否身份结构十分复杂/必须实例级一致？
          ├─ 是 → C：结构代理 + 局部生成
          └─ 否 → A：整图参考联合生成（快）
```

### 21.5 低成本与高精度的运行顺序

`分析→几何候选→低清候选→硬约束筛选→高质量局部生成→软约束筛选→后处理→导出`。在几何还错误时直接花费高成本进行高清精修会浪费预算。允许分为两级：常规图像全自动处理和低置信样本人工审核；但不要以低分辨率候选的轻微模糊掩盖部件错误。

## 22. 通用 JSON 配置规范（示例可落地）

### 22.1 完整示例的语义说明

附带 `config/example_task.json` 是一个**假设性、供工程配置演示的多物品任务**，示意在 2048×1152 废料背景中放储罐、灭火器。它不是本次真实案例当时提交给生成器的参数；物体实际长宽、投影框和放置中心在没有标定前应保持低置信度或由用户进一步确认。

核心字段：

```json
{
  "schema_version": "2.0",
  "task_id": "scrap_multi_001",
  "mode": "B",
  "background": {
    "path": "inputs/scenes/scene_001/background.jpg",
    "width": 2048,
    "height": 1152,
    "protect_overlay_text": true
  },
  "objects": [
    {
      "id": "tank_001",
      "category": "horizontal_pressure_vessel",
      "material_parts": {
        "shell": "unknown_metal",
        "manway": "metal",
        "seals": "rubber"
      },
      "identity_level": "component",
      "dimensions": {"known": false, "units": "m"},
      "placement": {
        "box_type": "oriented",
        "coordinate_space": "normalized_original_background",
        "center": [0.47, 0.54],
        "width": 0.46,
        "height": 0.35,
        "rotation_deg": 8,
        "status": "hypothetical_not_calibrated"
      },
      "ageing": {"level": 3, "allow_structural_damage": false}
    }
  ],
  "constraints": {
    "require_support": true,
    "require_foreground_occlusion": true,
    "background_protection": true,
    "protect_key_components": true
  }
}
```

**填写规则**：`normalized` 框只能描述完整投影的示意目标，不能当成真实物体尺寸来源；任何 `known=false` 的真实尺寸不得在后续代码里当作 0 米；姿态角 `rotation_deg` 是图像平面角，不是相机世界坐标下的 roll/yaw/pitch。

### 22.2 建议给每个字段增加证据与误差

例如：

```json
{
  "estimate": 0.46,
  "interval": [0.40, 0.52],
  "confidence": "low",
  "method": "manual_visual_range",
  "source": "scene_reference_only",
  "human_confirmed": false
}
```

当场景没有可核实尺度证据时，软件应展示多个布局候选供确认，而不是自动把 `estimate` 写进 `measured_length_m`。对多物品同时生成，可为每个物品使用独立 `confidence` 和 `allowed_occlusion_fraction`。

### 22.3 图像操作的约定

- 所有 Mask 默认与**原背景宽高相同**，单通道 8-bit，0 表示否、255 表示是；半透明/软 Mask 需要另加元数据 `mask_type=float_alpha`。
- 坐标采用左上角原点 `(0,0)`、x 向右、y 向下；OBB 的正角定义必须在同一工程中一致。
- 原图片的 RGB 颜色空间与 OpenCV BGR 的代码使用区别必须注明。
- 进行 JPEG 输出时，应保留一份无损结果和它的哈希，以供背景差分和训练标注。

## 23. 可执行 Python 工具与边界（此交付包附带脚本）

### 23.1 为什么要把“可运行”与“模型生成”分开

脚本 `scripts/fusion_utilities.py` 只做**确定性的图像检查、尺度计算、保护区像素差分、蒙版叠加及已验证参数的校色**。它**不能**调用图像生成模型、不会自动推断准确深度、不能替代人工/分割器创建高质量 Mask，也不宣称“已经解决所有贴图感”。把这些基础操作抽成工具的意义，是让自动化系统的每次调用都能有可复现的输入输出边界。

### 23.2 使用依赖与命令

```bash
python -m pip install numpy opencv-python

# 查看图像尺寸、模式与 RGB 全图均值（用于数据检查）
python scripts/fusion_utilities.py inspect --input scene.jpg

# 假设参照物与目标投影方向可比，计算演示尺度（注意假设）
python scripts/fusion_utilities.py scale \
  --reference-pixels 160 --reference-meters 0.8 \
  --object-meters 1.2 --relative-depth 1.1 --direction-factor 1.0

# 对两张已注册同分辨率的图，在保护 Mask 范围内比较差异
python scripts/fusion_utilities.py compare-background \
  --original original.png --composite final.png \
  --protect-mask masks/protect.png --tolerance 0

# 把原背景在保护区的像素恢复出来（无损 PNG）
python scripts/fusion_utilities.py restore-protected \
  --original original.png --composite generated.png \
  --protect-mask masks/protect.png --output restored.png

# 在已知物体可见 Mask 下进行简单合成（仅用于基线/调试）
python scripts/fusion_utilities.py composite \
  --background original.png --object-layer rendered_object.png \
  --visible-mask masks/object_visible.png --output baseline.png

# 复现本次真实案例的整帧 LAB + 高斯 + JPEG 参数
python scripts/fusion_utilities.py grade-case \
  --input second_round.png --output final.jpg
```

**边界与使用顺序**：`composite` 只是生成未经完整物理融合的基线，用来检查 OBB/Mask/前景遮挡位置。要消除贴图感，还需要将合成结果送入具备交互关系的局部生成/渲染与光照处理阶段，**不应把 `composite` 的输出直接当最终结果**。

### 23.3 一段不依赖特定服务商的总调度伪代码

```python
for task in tasks:
    profile_o = object_parser(task.object_images)
    profile_s = scene_parser(task.background)
    scale_candidates = placement_solver(profile_o, profile_s,
                                        task.known_dimensions,
                                        task.placement_constraints)
    for placement in scale_candidates:
        if not valid_support_and_collision(placement, profile_s):
            continue
        masks, interaction = build_mapped_interaction(placement, profile_s)
        ageing_plan = plan_ageing(profile_o.material_parts,
                                  profile_s.environment)
        for candidate in generator.generate_candidates(
                refs=task.object_images, scene=task.background,
                placement=placement, masks=masks,
                interaction=interaction, ageing=ageing_plan):
            hard = check_identity_scale_support_occlusion_background(candidate)
            if not hard.pass_all:
                feedback = classify_failure(hard)
                candidate = revise_at_failed_stage(candidate, feedback)
                continue
            candidate = harmonize_only_allowed_regions(candidate, masks)
            soft = check_lighting_material_edges_camera_style(candidate)
            if soft.acceptable:
                export_with_masks_provenance(candidate, task, masks)
                break
    else:
        export_failure_report(task, reason="NO_VALID_CANDIDATE")
```

伪代码展示模块化责任，`object_parser`、`generator.generate_candidates` 等仍需接入真实服务或实现；**不能误认为附带脚本已经具备这些未接入的模型能力**。

## 24. 数据集输出与可复现记录

### 24.1 为什么仅一张 JPG 不够

用于目标检测/分割的合成数据至少应知道“图中哪几个像素属于新物体”“哪些部件被遮挡”“原背景哪里发生了合法变化”。否则，如果再用一个不准确的自动分割模型补 Mask，就会把分割误差作为训练真值引入数据集。

### 24.2 检测/分割标签的建议字段

`sample_id`、`image_file`、`source_scene_id`、`source_object_ids`、`category_ids`、`bbox_xywh`、`segmentation_visible`、`segmentation_amodal`（完整形体，可选）、`keypoints`、`occlusion_ratio`、`truncation`、`synthetic=true`、`placement_uncertainty`、`review_status`。可参考 COCO 风格编码，但是**可见 Mask 与完整 amodal Mask 的概念不能混用**。

### 24.3 来源记录模板

```json
{
  "synthetic": true,
  "source_scene_sha256": "<sha256>",
  "source_object_sha256": ["<sha256>"],
  "editing_mode": "B",
  "models_used": [{"provider": "<actual provider>", "name": "<actual model>"}],
  "parameters": {"only_logged_public_controls": true},
  "generated_at": "<timestamp>",
  "reviewer": "<reviewer or automated gate>",
  "verification": {
    "background_pixel_lock": "PASS/FAIL/UNKNOWN",
    "geometry": "PASS/FAIL/UNKNOWN",
    "human_review": "PASS/FAIL/NOT_DONE"
  }
}
```

监控画面的日期叠字在合成图中保持完整，**不代表该物品真实出现在那个日期的现场**。应在文件名、数据库和对外展示中明确合成属性，避免与原始录像证据混淆。

### 24.4 数据质量抽检与防止模型“学到造假痕迹”

- 训练/测试划分以**原始场景、设备实例或视频序列**为单位，避免同一张背景的近重复合成图同时出现在训练集和测试集。
- 保留一部分真实拍摄且有真实标注的验证数据，检验模型是否只在合成域表现好。
- 采样时均衡不同尺度、位置、材质、遮挡程度、光照和相机质量，不能所有合成物体都位于画面中心。
- 针对异常高频、统一锈斑纹理、反复出现的 JPEG 压缩伪影做偏差分析。
- 对类别混淆、背景误改、边界伪影建立拒收与回炉通道。

## 25. 对照实验和最小可行验证方案

### 25.1 至少做六组消融实验

| 实验 | 改变的因素 | 需对比的结果 | 预期回答的问题 |
|---|---|---|---|
| E0 | 直接 Alpha 叠加（基线） | 接触/边缘/遮挡错误率 | 为什么简单贴图失败？ |
| E1 | A：整图生成 vs B：局部重绘 | 视觉评分和背景改动 | 哪种更满足用途？ |
| E2 | 是否提供目标 OBB/尺度区间 | 尺度误差/成功率 | 显式大小约束有多少帮助？ |
| E3 | 是否提供前景遮挡图 | 遮挡错误和边缘评分 | 哪种贴图感来自前后关系？ |
| E4 | 是否单独建模接触阴影 | 浮空率/接触评分 | 阴影带来多大增益？ |
| E5 | 按材质旧化 vs 统一锈迹 | 材质误分类与人评 | 旧化应如何区分材料？ |
| E6 | 整图校色 vs 局部调色 | 背景差分/局部光度 | 全图匹配是否损坏原图？ |
| E7 | 多视图结构控制 vs 只有单图 | 身份关键点准确率 | 多视图能减少哪些结构幻觉？ |

每组保持**输入场景、目标物件、模型版本、评价协议**一致；随机生成时记录可得 seed 和多个重复候选，避免因单次偶然结果下结论。不同成本下可以先做小规模人工评价，再用自动化指标筛选。

### 25.2 建议设计一个交叉测试矩阵

对象轴：刚性金属（罐体/工具）、涂漆金属（灭火器）、塑料、玻璃、木/纸、柔性布料。场景轴：废铁堆、干净仓库、室外地面、监控低清图、夜间/强反射。对每种组合至少收集：可行放置、可检验参照尺度、成功样本、失败样本、人工根因标注。此矩阵将帮助发现“只在废铁堆中表现好”的过拟合。

### 25.3 失败样本本身是优化数据

保存 `failure_type`、输入类别、环境标签、真实像素/参照尺度证据、生成控制版本以及人工修正动作；从这些记录中统计最常见的失败链条，例如：`背景单目尺度不确定 → 目标过大 → 支撑错位 → 阴影缺失 → 被判贴图感`。优化时应优先提升最上游尺度估计，而不是只给后处理增加随机阴影。

### 26.2 每个样本的逐步施工清单（操作顺序不可随意颠倒）

1. [ ] 冻结原图、计算哈希和尺寸、明确坐标/颜色空间。
2. [ ] 建立物体部件树，标注不可修改的身份关键点。
3. [ ] 给每个部件指定材质、涂层及允许的旧化/损伤。
4. [ ] 标注原背景中的支撑面、前景遮挡、禁止编辑区域。
5. [ ] 取得物体尺度证据，确定绝对尺寸或不确定区间。
6. [ ] 在原图坐标系中选放置 ROI、目标 OBB 和候选 3D 姿态。
7. [ ] 检查投影、承重、碰撞，淘汰不可行放置。
8. [ ] 建立前后遮挡图、接触图和合法交互区域。

10. [ ] 分部件设计旧化和环境交互，不统一刷随机锈斑。
11. [ ] 评估背景光照、局部颜色、锐度和压缩风格。
12. [ ] 根据 A/B/C 路线准备模型真实支持的条件输入。
13. [ ] 生成首批低成本候选并记录真实提示/参数。

### 26.3 遇到问题时返回哪一步

**尺寸不对 → S05**；**关键件反向/缺失 → S02/S06**；**支撑不合理 → S07**；**钢条被吃掉/遮挡冲突 → S07/S08**；**满脸红锈/材质失真 → S09**；**光源不对 → S10**；**背景改写 → S08/S11 路线选择**；**太清晰/色温不对 → S14**；**标注不可靠 → S15/数据集导出**。越靠上游的问题越应该优先修，避免造成越来越大的下游补丁。

## 27. 最后给实际工程的十条原则

1. **相对尺度不是绝对物理尺寸**：没有米数和标定时，请表达不确定性。
2. **完整形体尺寸与可见面积是两件事**：遮挡不应改变物体本身尺度。
3. **物理关系优先于视觉精致**：漂浮、穿模、反光方向错误不能靠高细节掩盖。
4. **防贴图感需要交互生成/重建**：前景遮挡、承重、接触阴影是关键，而不是单纯羽化。
5. **旧化必须随材料变化**：不要所有物品统一锈化。
6. **先结构再材质再摄影风格**：这是最节省反复生成成本的修复顺序。
7. **适当的遮挡比完整展示更像真实场景**：但数据集应记录可见度并保护关键识别目标。
8. **背景锁定要用 Mask 和像素恢复实现**：仅靠“不要改变背景”的提示不足以保证。
9. **评估要独立于生成**：生成器自信不等于几何/像素验收达标。
10. **每张合成图都要可追溯**：保存证据等级、输入哈希、配置、候选与审核，不冒充未加工照片。

# 附录 D：如何处理缺数据与无法确认的情况

- **不知道真实尺寸**：输出图上物品大小只是“视觉合理候选”，附加 `scale_confidence=low`；若任务要求物理尺度准确，必须补尺寸或标定数据。
- **六视图存在互相矛盾的接口**：停止实例级生成；优先确认原始产品资料，而不是自由创造结构。
- **不知道现场光源**：可以拟合现有阴影的视觉统计，但不能宣称真实灯位；有夜间多光源时优先局部编辑方案。
- **新物体会挡住监控水印**：调整放置，或者明确这张是模拟图；不能重绘“看似真实”的旧水印来暗示实物曾出现。
- **模型无法提供 Mask 或尺寸条件**：要么把结果标为视觉展示模式，要么另接受控编辑器；不能伪装模型已经满足硬约束。
- **生成结果过于完美、像 AI**：先看构图是否被重排、遮挡是否太整齐、旧化是否重复、锐度是否不合背景，再查具体失败项；不要仅靠增加随机噪声制造真实性。

**结束语**：可推广系统的核心不是一条超长 Prompt，而是由**可核查的物品身份、目标尺度、三维投影、支撑与遮挡、材质旧化、光照相机模型、背景保护以及闭环验收**组成的施工流程。实际储罐案例说明参考图联合重绘能够快速形成较自然的堆叠观感，但若要用于更复杂多物品、更多场景和训练数据集，必须把“隐式视觉判断”逐步升级为“显式、可测量、可失败、可回退”的约束。
